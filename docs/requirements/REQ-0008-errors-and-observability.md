# REQ-0008：例外處理與可觀測性

**狀態**：草稿
**日期**：2026-09-06

## 使用者要什麼

出錯的時候**看得懂發生什麼、知道下一步做什麼**；
真的要求助時，能把診斷資訊交出去，**而不用連自己的資料一起交出去**。

## 驗收條件

- [ ] 每個錯誤碼在 `architecture/error-codes.md` 有
      **「成因」與「使用者該做什麼」**兩欄，兩欄都不得空白。
- [ ] **UI 只顯示繁體中文訊息，錯誤碼只進日誌。**
- [ ] 每次操作帶 `correlation_id`，**UI 上可以複製**。
- [ ] **AST 測試比對 `src/domain/errors/` 與 `error-codes.md`** ——
      任一邊多一個或少一個就紅。
      （`src/domain/errors/` 是碼的單一真實來源，文件是它的說明。）
- [ ] **單一項目失敗不讓整批失敗** —— run 進 `部分失敗`，
      其餘照常寫入（REQ-0002 的同一條，在這裡是全域規則）。
- [ ] **診斷匯出去識別化**：不含使用者名、機器名、絕對路徑，
      也不含任何來源內容或筆記內容；**匯出後可以先人工檢視再送出**。
- [ ] `Verify.ps1 -Report` 產出的環境快照同樣去識別化 ——
      只留 Node／npm 版本、OS 版本、WebGL 能力這類**與人無關的事實**。
      （否則公開前檢查會掃到我們自己產的檔。）
- [ ] **失敗路徑**：未預期的例外也要有碼（`*_UNEXPECTED`）與 `correlation_id`，
      **不得出現英文 stack trace 直接噴到使用者畫面上**。

## 刻意不做

- **遠端遙測。** **任何東西都不往外送。** 這是單機工具，
  而它持有的資料是使用者蒐集的東西。
- **崩潰回報服務。**
- **把錯誤碼顯示給使用者當主要訊息。** 碼是給日誌與回報用的。
