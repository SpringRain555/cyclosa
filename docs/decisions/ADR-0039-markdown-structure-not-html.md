# ADR-0039 Markdown 在伺服器解析，閱讀器照結構畫，不用 `v-html`

- 狀態：**提案**（2026-10-28，給使用者看過摘要之後才實作）
- 依據：2026-10-28 另一個專案的試用回饋 4 —— 匯入的 Obsidian 筆記在閱讀器裡把 frontmatter、`#`、`**`、`[[…]]` 原樣顯示；
  使用者選「在閱讀器渲染 Markdown」，Stage 23 的筆記附件一起渲染
- 補充：`web/src/views/ReaderView.vue` 檔頭「正文為什麼是純文字段落」；ADR-0010（點註錨在不可變快照）；
  ADR-0019（PDF 版面選取要換算回正文）；ADR-0036（本機伺服器只收自己頁面的請求）
- 實作（預定）：`src/domain/text/blocks.ts`、`src/infrastructure/extract/markdown.ts`、`web/src/components/MarkdownBlocks.vue`、
  `tests/guards/no-v-html.test.ts`

## 背景

### 一、現在 `.md` 怎麼走

匯入時走純文字那一條：正文（`derived/` 的 `text`）就是原文，**frontmatter 與記號都在裡面**。閱讀器把正文切成段落、
當純文字畫出來。v1.0.1 只修了標題（`domain/ingest/markdown.ts`），顯示沒動。

### 二、為什麼不能直接 `v-html`

閱讀器跟 API 同一個 origin。CommonMark 允許在 Markdown 裡寫 HTML，而 `.md` 不一定是使用者自己寫的 ——
`text/markdown` 的網址也會被抓進來。把它 `v-html` 進頁面，裡面的腳本就能打 Cyclosa 自己的 API；
ADR-0036 擋的是**別的網頁**送來的請求，擋不了同一個頁面裡的腳本。`ReaderView.vue` 的檔頭早就寫了：
要排版得先引一個消毒器，**那是一個獨立的決定**。這一份就是那個決定 —— 結論是不需要消毒器。

### 三、點註錨在正文的字元區間上

點註存 `TextQuoteSelector` ＋ `TextPositionSelector`（ADR-0010），對的是 `derived/` 的 `text`。
畫面上的選取靠每一段的 `data-start` 加上 `offsetWithin`（數前面的文字節點）換算回正文的位置。
**畫面上的文字跟正文不一樣，這一套就要另外一張對照表**（PDF 版面那一次就是，ADR-0019、`mapBetween`）。

## 決定

### 一、在伺服器解析，產物是 `{ text, blocks }`

抽取時把 Markdown 解析一次：

- **`text` 是畫面上看到的文字**：frontmatter、`#`、`**`、`[[…|…]]` 的括號都不在裡面，區塊之間用換行隔開。
  檢索索引、初讀、抽取、引文定位、點註全部錨在它上面 —— 地位跟網頁走 Readability 之後的正文一樣。
- **`blocks` 只記結構與位置，不含任何 HTML 字串**。每一個片段是 `text` 的一段 `[start, end)`：
  - 區塊：段落、標題（1–6 級）、清單（有序、無序、巢狀、待辦）、引用、提示框（`> [!note]`）、程式碼區塊、表格、分隔線
  - 行內：粗體、斜體、刪除線、標記（`==…==`）、行內程式碼、連結、wiki 連結、圖片佔位
- 存在 `derived/<itemId>.v3.json`：`DerivedPayload` 多一個選填的 `blocks`。**不變式有測試釘著**：
  每個片段都在 `text` 範圍內、照順序、不重疊，片段的文字就是 `text` 的那一段

### 二、閱讀器用 Vue 範本逐塊畫，全程不用 `v-html`

新元件 `MarkdownBlocks.vue`。每個區塊元素帶 `data-start`，**元素裡的文字節點一字不多、一字不少** ——
現有的選取換算原樣可用，不需要對照表。點註的高亮把行內片段再切開。
清單的項目符號、提示框的標題、表格線都是樣式，不是文字節點（否則換算會多算字）。

### 三、安全：不靠消毒器，靠「根本不產生 HTML」

- **原始 HTML 當文字顯示**，不解析成元素
- **連結只認 `http:`、`https:`、`mailto:`**：新分頁開、`rel="noopener noreferrer"`；其餘（`javascript:`、`data:`、相對路徑）顯示成文字
- **圖片不載入**：顯示替代文字與網址（網址可以點、另開分頁）。瀏覽器自己去抓等於繞過唯一的擷取管線
  （節流、robots、快照都不在），也會讓圖片主機知道你正在讀哪一份。Obsidian 的 `![[附件]]` 本來就不在快照裡
- **新守門 `no-v-html`**：`web/src` 不得出現 `v-html`、`innerHTML`、`outerHTML`、`insertAdjacentHTML` ——
  這一條讓「不用 `v-html`」不只是這一個元件的寫法，而是整個前端的規則

### 四、解析器：`marked`，只用它的 lexer

MIT、零相依（2026-10-28 查 registry）。**釘 18.1.1** —— 18.1.2 是兩天前才發佈的，選已經發佈滿兩週的那一版。
只用它的 lexer 拿 token，**不用它產生 HTML**。Obsidian 的語法（`[[a]]`、`[[a|b]]`、`![[a]]`、`==標記==`、提示框）
用它的擴充介面寫在我們這邊；數學式照原文顯示。

### 五、`EXTRACTOR_VERSION` 3

`EXTRACTOR_CHANGES[3] = ['text']`。`.txt` 也是 `text` 這一種，會被標成「舊版抽的」一次，按「重算全部正文」就消 ——
寧可多標一次，也不為了它另立一種資料。舊的 `.md` 照讀舊版產物（`readDerived` 找不到新版退回舊版），
重算時點註與關聯引文由既有的重解機制對回；引文裡帶記號的那幾條會對不到，照現有規則標出來，不刪。

### 六、語言偵測與標題都在 `text` 上做

v1.0.1 的標題規則（frontmatter → 一級標題 → 檔名 → 第一行）不變；語言偵測改在拿掉記號之後的文字上做。

### 七、筆記附件用同一個元件

Stage 23 的 Markdown 筆記附件：伺服器讀附件時解析回 `blocks`，閱讀器與關聯圖的附件檢視用同一個元件畫。
附件沒有錨點；**附件的全文檢索內容這一版不改**（仍是原文）。

## 考慮過但沒選的

| 方案 | 為什麼不選 |
|---|---|
| 在瀏覽器解析，`v-html` ＋ DOMPurify | 同源頁面上跑外來 HTML，安全只靠消毒器那一層；多一個要維護的依賴；選取還要從渲染後的 DOM 換回原文位置，跟 PDF 版面一樣要一張對照表 |
| 拿掉記號、存乾淨正文，**不渲染** | 使用者選了渲染：筆記的標題、清單、粗體是內容的一部分 |
| 正文保留原文（含記號），只在畫面上渲染 | 檢索、抽取、引文都會吃到 `**`、`[[`：模型引的一句在原文裡帶著記號，畫面上卻對不到同一串字 —— 兩份文字就需要對照表 |
| `markdown-it` | 它的 CLI 相依 `argparse` 是 Python-2.0 授權（寬鬆，但不在這個專案盤點過的授權裡）；token 一樣要自己轉位置 |
| `mdast-util-from-markdown`（micromark）| 結構最完整、還帶原文位置，但要二三十個小套件；`marked` 零相依就夠用時不引 |

## 代價

- 多一個依賴。`marked` 的 token 格式改版時轉換要跟著改 —— 每一種語法的 `{text, blocks}` 都有測試釘著
- `.txt` 會被標成舊版一次
- 引文裡帶記號的舊關聯，重算之後對不到原文（標示，不刪）
- 圖片不顯示 —— 要看圖就開原始快照或原網址

## 什麼情況要重新考慮

- **要在閱讀器裡顯示 Markdown 的圖片**：先決定「圖片也走擷取管線、存成快照」，不是讓瀏覽器自己去抓
- **網頁也想要排版**：同一套 `blocks` 可以從 Readability 的 DOM 產生 —— 那是另一份 ADR
