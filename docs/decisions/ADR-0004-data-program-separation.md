# ADR-0004：資料與程式分離，實際路徑不進版控，指標檔在 `%LOCALAPPDATA%`

**狀態**：已採用（設計決定；實作尚未開始）
**日期**：2026-09-06

## 背景

**這個 repo 預期會公開。** 而這個工具蒐集的東西 —— 快照、筆記、專題名稱、
來源清單 —— 全部是私人的。

更細一層的問題：**私人資料夾的「名字」本身就是資訊。** 把實際路徑寫進版控，
等於把「這個人有哪些專題」這份清單一起發佈出去，即使資料本身沒有進 repo。

上層規範（CONVENTIONS §11）已經訂了外部資料根的做法，這份 ADR 記的是
這個專案怎麼落地。

## 決定

1. **程式在 repo，資料在 `<資料根目錄>`**，兩者沒有父子關係。
2. **repo 內的所有文件一律用佔位符** `<資料根目錄>`／`<私人資料樹>`。
   實際路徑的權威來源有兩個，**都不在這個 repo 裡**：
   `D:\Projects\_meta\cards\cyclosa.md` 的 `data_root` 欄位，
   與本機那份 `.claude\settings.json`（不進版控，範本是 `.claude\settings.example.json`）。
3. **執行期靠指標檔** `%LOCALAPPDATA%\Cyclosa\system_paths.json` 找到資料根。
4. 資料根底下四個頂層資料夾：`cases\`、`backups\`、`logs\`、`tmp\`。

## 考慮過但沒選的

| 方案 | 為什麼不選 |
|---|---|
| **資料放 repo 底下 ＋ `.gitignore`** | 一次 `git add --force`、一次 gitignore 寫錯、一次 `git clean` 沒注意就外洩；而且路徑名還是會出現在文件與錯誤訊息裡 |
| **只用環境變數** | 沒設的時候會靜默退回預設值；不同終端（PowerShell／Git Bash／IDE）繼承的值不一致，除錯時分不出是設定錯還是程式錯 |
| **設定檔放 repo 根目錄** | 同第一項 —— 它遲早會被 commit 一次 |
| **每次啟動問使用者** | 對一個天天用的工具，這是把成本加在錯的地方 |

## 代價

- **多一層間接。** 出錯時錯誤訊息必須講清楚「指標檔在哪、它指到哪、那個路徑存不存在」，
  否則使用者只會看到一個空清單而不知道原因（這是 REQ-0001 的驗收條件之一）。
- **換機器要自己搬資料**，而且要重建指標檔。
- **文件裡到處是佔位符，可讀性變差** —— 讀的人得先知道佔位符指到哪。
- agent 在這個 repo 裡讀不到任何真實資料，除錯時要靠使用者轉述。**這是刻意的。**

## 什麼情況要重新考慮

- 需要多台機器同步時。那會是一個新的決定，而且第一個要回答的是
  **「同步的單位是專題資料夾還是 `case.sqlite`」** —— 兩者的衝突處理完全不同。
- 若某天這個 repo 確定永遠不公開，第 2 條（佔位符）可以放寬 —— 但第 1、3 條
  的理由與公開無關，仍然成立。
