# ADR-0024：已讀改標在標籤的字重上 —— 未讀粗體，已讀正常

**狀態**：已採用。**2026-09-09（v0.9.1）實作。**
**日期**：2026-09-09

## 背景

ADR-0018 給「已讀」的畫法是**灰色內環**（`#8b93a3`），
理由是「外環＝你在哪，內環＝讀過了」，兩個可以疊。

2026-09-09 的人工驗收裡，使用者看著截圖問的是：
**「為什麼資料的正方體周圍有白色的環？」** ——
一個記號要人回頭問它是什麼意思，它就已經失敗了。

追下去發現那不只是「不好認」，是**畫錯位置**：

| | 世界單位 |
|---|---|
| 已讀環的中心線 | 4.76 |
| 方塊的側影邊緣（正對著面）| 4.95 |
| 方塊的側影邊緣（角對著你）| 5.71 |

環比方塊的側影小，所以**方塊永遠吃掉它一部分**，
而吃掉多少隨著你轉動在變 —— 於是它時而是一圈、時而是幾段從角落露出來的弧。
這正好犯了 ADR-0022 拿來加粗焦點環的那一條：
**一個時有時無的記號比一個大記號更難讀。**

而且焦點節點上會疊成**三圈同心圓**（已讀、選取、焦點），
那正是使用者最常盯著看的那一個節點。

### 「顏色變淡」為什麼不行

使用者自己提的第一個方案是「顏色變淡」。它做不得，理由是通道已經滿了：

- **明暗在這張圖上的意思是遠近**（ADR-0018 規則 3）
- **不透明度是一跳鄰域的提亮**（0.72 ／ 1.0）

同一個通道再擠第三個意思，就分不出「這個讀過了」與「這個比較遠」。

## 決定

**已讀不再是一個環，改標在標籤的字重上：未讀 700，已讀 400。**
就是電子郵件那個做法 —— 使用者的原話是「學 Gmail」，
而那個慣例的價值正在於它不用學。

三件跟著訂下來的事：

1. **粗的是未讀，不是已讀。** 要跳出來的是「還沒看的」，
   而不是「已經處理完的」——這跟收件匣同一個道理。
2. **實體一律正常字重。** 實體不是一份可以讀的東西，
   它根本沒有已讀這件事。它跟「已讀的資料」靠形狀分得開（空心線框）。
3. **兩個字重是 700 與 400，不是 600 與 500。**
   中間值在只有 Regular 與 Bold 的字型上會被捨進同一個字重，
   於是兩種狀態長得一模一樣 —— 而那種壞法不會報錯，只會安靜地不生效。

規則寫在 `domain/graph/render-rules.ts` 的 `labelWeightFor`，
不在畫圖那一支：**「哪一種節點有已讀這件事」是一條規則，不是一個畫法。**

## 考慮過但沒選的

| 選項 | 為什麼沒選 |
|---|---|
| **環留著、放大到包住方塊** | 做得到，可用區間只有 1.90–2.15 倍（下限是方塊的角，上限是青色選取環的內緣）—— 但**焦點節點上仍然是三圈同心圓**，而那是最需要讀得清楚的一個 |
| 角落一個小灰點 | 不跟環搶同一圈，但它是一個**要重新學的新記號**，而且遠看很小 |
| 去彩度（低彩度的同色相）| 這是「顏色變淡」唯一繞得開衝突的版本，代價是低彩度的藍遠看會跟灰色的實體混 —— 而那兩者的分別是這張圖的根本 |
| 圖上完全不標，只在閱讀器清單標 | 最乾淨，但它把「哪些讀過了」整個從圖上拿掉 |

## 代價

- **標籤不在的時候，已讀就看不見了。** 兩種情況會這樣：
  語意縮放退到只剩形狀那一級（遠距離），以及超過 300 個標籤的上限。
  環在那兩種情況下也小到看不出來，但它至少還在。
- **一張新圖幾乎全是粗體** —— 因為多數東西都還沒讀。
  這是對的（要跳出來的正是那些），但它讓「粗體」在早期不太有資訊量。
- **字重的差別比一個環弱。** 這是換來的：它不再擋住方塊，也不再多一圈。
- 標籤是烘進貼圖的，所以**讀完之後要重畫那張圖才會變回正常字重** ——
  跟原本的環一樣（環的可見性也只在建物件時設一次）。

## 什麼情況要重新考慮

- **使用者主要在遠距離工作** —— 那時已讀在畫面上等於不存在，
  要嘛回到某種節點上的記號，要嘛接受它只是閱讀器的狀態。
- **標籤上限常態被超過**（一次看幾百個節點）—— 同上。
- **出現第二個要標在標籤上的狀態** —— 字重只有兩級，第二個狀態就沒有位置了。
