本資料夾的截圖使用產品的 `ConsolidateShellPanel` 與 `MergedEntities` 元件，以及共用樣式；外層為隔離的合成預覽頁。
API 回應由記憶體內的假資料提供，沒有啟動正式 App、讀寫使用者專題或呼叫模型。

- `review.png`：合併可勾選、預設不勾，執行按鈕停用。
- `unmerge.png`：模擬勾選與執行回應後，重新載入可看到實體面板的取消入口。

這些截圖只驗證介面接線與呈現，不代表真實模型品質或正式 App 的完整人工驗收。
實際候選篩選、資料庫合併／取消、來源關聯還原、失效與部分失敗，另由 `tests/e2e/consolidate-merge.test.ts` 驗證；
合併與抽取混合執行順序由 `tests/e2e/consolidate.test.ts` 驗證。

## 正式 App 與本機模型補驗

`app-merged.png` 與 `app-restored.png` 來自正式 App，使用 `sources/` 中三份合成文件，透過 Chrome 擴充套件實際匯入與操作；與上面的記憶體假 API 預覽分開。

規劃及抽取模型為 `granite4.2:8b`，嵌入模型為 `hf.co/mykor/granite-embedding-311m-multilingual-r2-GGUF:BF16`；兩道門檻為 5／0.97。三份文件抽取完成後有 6 個實體，整理規劃產生 1 組候選，僅建議合併研究中心的簡稱與正式名稱，預設不勾選。勾選執行成功後，側欄列出併入項目；取消後原「對外簡稱」關聯恢復。

合併前後的唯讀快照比對確認：取消後 15 條關聯的識別碼、端點、關係、狀態與全部 5 筆出處一致。孤立實體的搜尋、選取、合併狀態重載保存與取消後獨立選取，也已走過正式介面。

另實測同頁規劃中放棄：頁面維持已放棄，Ollama 載入清單變空。此結果只代表此組合成資料；正式資料的門檻品質量測仍由維護者進行。規劃失敗訊息保留已修正，本輪未另以失敗模型做人工畫面驗收。
