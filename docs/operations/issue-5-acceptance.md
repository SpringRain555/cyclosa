# Issue #5 驗收方法

## 已可自動驗證的項目

在專案根目錄執行 `.\tools\Verify.ps1`；測試使用合成資料及假嵌入，不需安裝或啟動模型。
`tests/e2e/consolidate-merge.test.ts` 涵蓋：兩道門檻、模型自行增加配對被排除、預設不勾、只執行勾選、取消還原關聯、
規劃後實體變動、部分失敗與交易回滾，以及嵌入未設定／維度不符／無效向量。
`tests/e2e/consolidate.test.ts` 驗證合併先於抽取，並保留既有抽進圖、取消、復原與 D4 測試。

## 正式 App 的人工操作（約 10–15 分鐘，不含模型等待）

1. 由使用者從檔案總管雙擊 `start_cyclosa.cmd`，確認這次開的是 issue5 的程式副本。建立一個新的合成專題，不使用私人資料驗收。
2. 如要只驗證勾選與執行，可由使用者在空專題套用既有 `consolidate-reviewing` 開發範例：先自行關閉 App，
   在此專案執行 `npx tsx tools/dev/seed-research.ts --data-root <測試資料根> --slug <空專題的slug> --state consolidate-reviewing`，
   再自行啟動 App。三個參數必須明確指定；工具只接受空專題。此步驟不呼叫模型。
3. 進入該專題的「匯入與研究」，找到「整理專題」。確認「合併實體」與兩條「抽取資料」可勾，且全部預設不勾；其餘操作仍標示不能執行。
4. 只勾「合併實體」，確認按鈕顯示 1，然後按「執行已勾選的操作」。預期這一筆只有合併，不會要求抽取模型；未勾的抽取不會執行。
5. 切到關聯圖並選取保留的實體；在面板找到「併入這個實體的項目」，應列出被吸收的名稱。
   按「取消合併」，預期項目消失；重新整理後仍維持已取消。若測試實體原本沒有關聯，可用圖上的搜尋／選取找到它，不以預設是否展開來判斷資料是否存在。
6. 進設定頁的模型設定，找到「整理的合併候選」。確認距離預設 5、相似度預設 0.97。
   改成距離 2、相似度 0.99，離開再回來，確認值保存；完成後可改回原值。

## 真實候選品質（維護者量測）

完整候選產生需設定本機嵌入模型，以及整理規劃使用的 `plan` 服務。使用含已知重複及非重複實體的合成專題，
按「開始整理規劃」，確認模型看到的候選範圍與被丟棄原因。存在名稱候選但嵌入未設定時應顯示設定錯誤，不會只靠名稱列出語意候選。

初始門檻 5／0.97 尚未在真實資料量測。維護者應記錄使用模型、兩個門檻、人工標註的真重複數、候選數、誤報與漏報數，
再決定正式使用的門檻。此量測不是自動測試或合成介面截圖可以替代的。

## 已完成的正式 App 補驗

合成來源、模型、候選結果與正式 App 截圖見 [驗收證據](evidence/issue-5/README.md)。已走過真實匯入、抽取、候選規劃、只勾合併、執行、取消、重載保存，以及原關聯／出處還原；同頁規劃中放棄也確認卸載本機模型。

規劃中途放棄應立即停止本次請求，不接受晚到的操作清單。沒有其他整理規劃或執行作業時，會要求卸載本次使用的規劃及嵌入模型；服務無法連線時不回復已放棄狀態，卸載失敗記入日誌。

若待合併實體原本互相關聯，合併期間保留原端點與出處，從子圖隱藏組內關聯，避免生成自連線；取消後恢復顯示。此情況已加入回歸測試。

## 邊界情況複查

新增回歸測試以虛構資料重現並修正：取消別名殘留、合併鏈、非逆序取消、封存操作、過期取消請求、損壞移動紀錄、並行送出、等待期間封存／取消勾選／放棄。
另驗證合併後新增給保留者的關聯保留不動、後續改過的端點不被覆寫，以及舊版移動紀錄陣列相容性。
新別名差異只對新合併紀錄存在；舊紀錄沒有完整資訊時不猜刪別名。不附 `mergeId` 的舊 API 客戶端維持原語義，新面板才提供過期請求保護。

本輪新增情境以自動回歸測試驗證；前面的真實 App 截圖是先前版本的人工驗收，不代表本輪新增的逆序取消、停用按鈕與版本識別碼畫面已實測。
