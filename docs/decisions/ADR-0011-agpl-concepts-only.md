# ADR-0011：AGPL-3.0 的專案只讀概念，一行程式碼都不抄、也不當依賴

**狀態**：已採用（設計決定；實作尚未開始）
**日期**：2026-09-06

## 背景

**2026-09-04 用 GitHub API 實查過每個對手的授權欄位**（不是憑印象）。
結果分成三組：

| 授權 | 專案 | 能怎麼用 |
|---|---|---|
| MIT | Aleph、ArchiveBox、GraphRAG、LightRAG、sigma.js、cosmos.gl、`3d-force-graph`、`d3-force-3d` | 概念與程式碼都可以借；後兩者直接當依賴 |
| Apache-2.0 | `@mozilla/readability`、trafilatura、cognee、Graphiti | 可當依賴 |
| **AGPL-3.0** | **Datashare、SingleFile、Karakeep、Zotero** | **只讀概念** |

而這個專案採 MIT（ADR-0012）。**AGPL 的傳染性會讓整份授權失效** ——
不是「有一部分是 AGPL」，是整個作品都要以 AGPL 條款發佈。

麻煩的是 AGPL 這一組裡有這個領域最成熟的實作：**SingleFile 的單檔快照**
大概是同類東西裡最完整的。

## 決定

1. **AGPL-3.0 的專案只讀概念：一行程式碼都不抄、也不當依賴。**
2. **市場調查裡每條判讀都要標明「借的是概念還是程式碼」**
   （`research/market-scan.md` 已經這樣寫）。
3. **加任何新依賴之前實查它的 `LICENSE`。**「我記得它是 MIT」不算 ——
   見 `research/index.md` 的可信度分級。
4. 這條規則同時寫進 `AGENTS.md`／`CLAUDE.md` 的「五條不可違反的規則」，
   因為它最可能被一個沒讀過這份 ADR 的 agent 違反。

## 考慮過但沒選的

| 方案 | 為什麼不選 |
|---|---|
| **整個專案改採 AGPL** | 那會讓 `domain/graph` 沒辦法被 `rubricator`（MIT）取用 —— 見 ADR-0014。三個專案一律 MIT 是刻意的一致性 |
| **用了但不發佈** | AGPL 對「透過網路提供服務」也觸發；而且「以後不會發佈」不是可以依賴的假設 —— 這個 repo 本來就預期公開 |
| **只抄「一小段」** | 授權不看行數 |
| **看到再說，出事再移除** | 移除的成本在寫完之後才發生，而且要證明「移乾淨了」比一開始不碰難得多 |

## 代價

- **有幾個現成的好東西不能用**，最明顯的是 SingleFile 的單檔快照 ——
  等價功能要自己寫，而且第一版一定比它差。
- **每次加依賴多一道查證步驟**（開 `LICENSE`、看 `package.json` 的 `license` 欄）。
- 判斷「這算概念還是實作」有時候不明確 —— 例如讀完別人的演算法之後自己寫，
  邊界在哪。**遇到不確定的就當成程式碼，不要當成概念。**

## 什麼情況要重新考慮

**不重新考慮 —— 這是授權事實，不是取捨。**

唯一會變的情況是**整個專案改授權**（那要另開一份 ADR 取代 ADR-0012），
而那件事本身要先回答：已經以 MIT 發佈的版本**改不回來**。
