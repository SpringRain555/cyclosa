# ADR-0039 Markdown 在伺服器解析，閱讀器照結構畫，不用 `v-html`；舊資料由 App 升級

- 狀態：**已採用**（2026-10-28）。提案給使用者看過摘要之後改了兩處：**圖片維持不載入**（使用者確認）；
  **舊資料要升級成新格式，不留讀舊格式的路**（使用者：「舊資料需要全部更新成配新版的，沒辦法就重新生成／處理，盡量不要兼容舊資料」）——
  原提案的「找不到新版退回舊版、按『重算全部正文』才換」整段改掉，見第五節
- 依據：2026-10-28 另一個專案的試用回饋 4 —— 匯入的 Obsidian 筆記在閱讀器裡把 frontmatter、`#`、`**`、`[[…]]` 原樣顯示；
  使用者選「在閱讀器渲染 Markdown」，Stage 23 的筆記附件一起渲染
- 補充：`web/src/views/ReaderView.vue` 檔頭；ADR-0010（點註錨在不可變快照）；ADR-0019（PDF 版面選取要換算回正文）；
  ADR-0036（本機伺服器只收自己頁面的請求）
- 實作：`src/domain/text/markdown-blocks.ts`（區塊型別、不變式、位置換算）、`src/infrastructure/extract/markdown.ts`（解析）、
  `src/application/case-upgrade.ts`（升級）、`src/interface/http/upgrade-gate.ts`、`web/src/components/MarkdownBlocks.vue`、
  `tests/guards/no-v-html.test.ts`、migration `016-derived-version.sql`

## 背景

### 一、v1.0.1 之前 `.md` 怎麼走

匯入時走純文字那一條：正文（`derived/` 的 `text`）就是原文，**frontmatter 與記號都在裡面**。閱讀器把正文切成段落、
當純文字畫出來。v1.0.1 只修了標題（`domain/ingest/markdown.ts`），顯示沒動。

### 二、為什麼不能直接 `v-html`

閱讀器跟 API 同一個 origin。CommonMark 允許在 Markdown 裡寫 HTML，而 `.md` 不一定是使用者自己寫的 ——
`text/markdown` 的網址也會被抓進來。把它 `v-html` 進頁面，裡面的腳本就能打 Cyclosa 自己的 API；
ADR-0036 擋的是**別的網頁**送來的請求，擋不了同一個頁面裡的腳本。`ReaderView.vue` 的檔頭原本寫著：
要排版得先引一個消毒器，**那是一個獨立的決定**。這一份就是那個決定 —— 結論是不需要消毒器。

### 三、點註與引文錨在正文的字元區間上

點註存 `TextQuoteSelector` ＋ `TextPositionSelector`（ADR-0010），關聯的引文存 `quote` ＋ `char_start`／`char_end`，
對的都是 `derived/` 的 `text`。畫面上的選取靠每一段的 `data-start` 加上 `offsetWithin`（數前面的文字節點）換算回正文的位置。

## 決定

### 一、在伺服器解析，產物是 `{ text, blocks }`

抽取時把 Markdown 解析一次：

- **`text` 是畫面上看到的文字**：`#`、`**`、`[[…|…]]` 的括號、清單符號都不在裡面。區塊之間用空行隔開、清單項目與表格列用換行、
  儲存格用 tab —— 這些分隔字元不屬於任何區塊。檢索索引、初讀、抽取、引文定位、點註全部錨在它上面，
  地位跟網頁走 Readability 之後的正文一樣。
- **frontmatter 不丟**：顯示成最上面一塊「文件屬性」（原樣的 `key: value` 幾行，等寬淡色），也留在 `text` 裡 ——
  Obsidian 的 `tags`、`aliases` 是使用者寫的內容，拿掉就搜不到。語言偵測跳過這一塊（英文的鍵名會把短的中文筆記判成英文）。
- **`blocks` 只記結構與位置，不含任何 HTML 字串**。每一個片段是 `text` 的一段 `[start, end)`：
  - 區塊：文件屬性、段落、標題（1–6 級）、清單（有序、無序、巢狀、待辦）、引用、提示框（`> [!note]`）、程式碼區塊、表格、分隔線、原始 HTML
  - 行內：粗體、斜體、刪除線、標記（`==…==`）、行內程式碼、連結、wiki 連結、嵌入（`![[…]]`）、圖片、行內 HTML
- `DerivedPayload` 多一欄 **`blocks`：Markdown 是陣列，其餘種類是 `null`**（必填欄位，見第五節）。
  **不變式有測試釘著**：每個片段都在 `text` 範圍內、照順序、不重疊，行內片段在所屬區塊裡面
- HTML 實體（`&amp;`）照原文顯示，不解碼 —— 解碼會讓正文跟原文的字數對不上，而筆記裡幾乎不會出現

### 二、閱讀器用 Vue 逐塊畫，全程不用 `v-html`

新元件 `MarkdownBlocks.vue`。**只有放文字的那一層元素（段落、標題、儲存格、程式碼、文件屬性、提示框標題）帶 `data-start`**，
而它裡面的文字節點一字不多、一字不少 —— 現有的選取換算原樣可用。點註的高亮把行內片段再切開。
清單符號、待辦方框、提示框的預設標題、圖片網址都是樣式或放在帶 `data-start` 的元素外面，不是那一層裡的文字節點
（否則換算會多算字）。段落裡的單一換行照原文斷行（Obsidian 預設就是這樣顯示）。

### 三、安全：不靠消毒器，靠「根本不產生 HTML」

- **原始 HTML 當文字顯示**，不解析成元素
- **連結只認 `http:`、`https:`、`mailto:`**：新分頁開、`rel="noopener noreferrer"`；其餘（`javascript:`、`data:`、相對路徑）顯示成文字。
  伺服器先判一次（`href` 只在安全時給），前端再判一次
- **圖片不載入**（2026-10-28 使用者確認）：顯示替代文字，網址放在提示裡、可以另開分頁。讓瀏覽器自己去抓等於開了第二條抓取的路 ——
  robots、節流、私人位址阻擋（ADR-0038）、快照與 manifest 都不在；圖片主機每一次都會知道你正在讀哪一份；圖之後被換掉也沒有快照可以對。
  原始快照頁的 CSP 本來就是 `img-src data:`。Obsidian 的 `![[附件]]` 本來就不在快照裡
- **新守門 `no-v-html`**：`web/src` 不得出現 `v-html`、`innerHTML`、`outerHTML`、`insertAdjacentHTML` ——
  這一條讓「不用 `v-html`」不只是這一個元件的寫法，而是整個前端的規則

### 四、解析器：`marked`，只用它的 lexer

MIT（`LICENSE` 另附它移植的 Markdown.pl 的 BSD 條款）、零相依（2026-10-28 查 registry 與裝好的 `package.json`）。
**釘 18.1.1** —— 18.1.2 是兩天前才發佈的，選已經發佈滿兩週的那一版。只用它的 lexer 拿 token，**不用它產生 HTML**。
Obsidian 的語法（`[[a]]`、`[[a|b]]`、`![[a]]`、`==標記==`）用它的擴充介面寫在我們這邊；提示框是「第一段以 `[!類型]` 開頭的引用」，
在 token 上認；數學式照原文顯示。

**位置**：marked 的 token 只有 `raw`，沒有在原文裡的位置。頂層 token 的 `raw` 接起來就是原文（18.1.1 實測），
往下一層（引用拿掉了 `> `、清單拿掉了縮排）就不是了 —— 所以每一段輸出的文字**一行一行地**在它那個 token 的範圍裡找回原文位置，
得到「正文第 i 個字 ↔ 原文第幾個字」的對照表。它不存檔，只在第五節的升級裡用。

### 五、`EXTRACTOR_VERSION` 3，舊資料由 App 自動升級

`EXTRACTOR_CHANGES[3] = ['text']`。**不再有「舊版抽的正文」這種狀態**：

- **什麼時候升**：每一個帶 `:slug` 的請求進路由之前（`upgrade-gate.ts`），那個專題的 `case.derived_version`（schema v16）
  比 `EXTRACTOR_VERSION` 舊就先升級、升完才處理請求。同一個程序裡每個專題只檢查一次；同時進來的請求等同一次升級。
  **不在啟動時把全部專題升完** —— 那會拖慢啟動，而啟動器等 healthz 是有時限的
- **怎麼升**：抽取有改過的種類（照 `EXTRACTOR_CHANGES`）從快照重抽；**沒改過的種類只把 `derived` 檔換成新版號**
  （內容不變，`blocks: null`）；舊版號的檔一律刪掉。`readDerived` **只讀現行版**，閱讀器的「這份是舊版抽的」提示拿掉
- **正文真的變了的那幾份**（純文字 `.txt` 重抽出來一字不差，那些什麼都不動）：
  - 重建全文索引；**向量作廢、不在升級時重算** —— 重算要載入嵌入模型，而這台機器的 GPU 是幾個專案共用的；
    作廢的那幾份出現在「還沒有向量」的計數裡，用既有的回填補
  - **關聯的引文與點註換到新正文**：先在舊正文確認它原本的位置（位置對不上就先找字），再用第四節的對照表換到新正文，
    **引文與點註的文字改成新正文的那一段**（也就是拿掉記號之後畫面上看得到的樣子），`notes\<id>.md` 跟著重寫。
    沒有對照表的（非 Markdown 的重抽）照既有的找字。**對不上的留著、數出來**，不刪
- **筆記附件**：標題改用 v1.0.1 的 Markdown 標題規則，索引與摘要改成看得到的文字（附件沒有點註，不必換位置）
- **結果寫一則專題升級通知**（`case_notice`，只有真的有變才寫）：重抽幾份、引文與點註換了幾條、對不上幾條、幾份要回填向量
- **失敗**：單一份重抽失敗不擋整個專題（數進通知）；資料庫開不起來交給原本那個請求自己的錯誤
- 「重算全部正文」那顆按鈕留著，當成手動的整批重來；它跟升級用同一支重抽

### 六、語言偵測與標題

v1.0.1 的標題規則（frontmatter → 一級標題 → 檔名 → 第一行）不變；語言偵測改在 `text` 上做、跳過文件屬性那一塊。

### 七、筆記附件用同一個元件

Stage 23 的 Markdown 筆記附件：伺服器讀附件時解析回 `{ text, blocks }`，閱讀器與關聯圖的筆記欄用同一個元件畫。
附件沒有錨點。新附上的附件，索引與摘要就用看得到的文字；舊的由第五節的升級補。

## 考慮過但沒選的

| 方案 | 為什麼不選 |
|---|---|
| 在瀏覽器解析，`v-html` ＋ DOMPurify | 同源頁面上跑外來 HTML，安全只靠消毒器那一層；多一個要維護的依賴；選取還要從渲染後的 DOM 換回原文位置，跟 PDF 版面一樣要一張對照表 |
| 拿掉記號、存乾淨正文，**不渲染** | 使用者選了渲染：筆記的標題、清單、粗體是內容的一部分 |
| 正文保留原文（含記號），只在畫面上渲染 | 檢索、抽取、引文都會吃到 `**`、`[[`：模型引的一句在原文裡帶著記號，畫面上卻對不到同一串字 —— 兩份文字就需要對照表 |
| 舊資料照讀舊版產物，使用者按「重算全部正文」才換（原提案）| 使用者不要半新半舊：同一個專題裡有的筆記渲染、有的不渲染，`.txt` 被標「舊版」，帶記號的引文只標「對不到」 |
| 啟動時把所有專題升完 | 拖慢啟動；啟動器等 healthz 有時限。沒開過的專題晚一點升，看起來沒有差別 |
| 升級時順便重算向量 | 要自動載入本機嵌入模型；GPU 共用，不在使用者沒按任何東西的時候載入 |
| `markdown-it` | 它的 CLI 相依 `argparse` 是 Python-2.0 授權（寬鬆，但不在這個專案盤點過的授權裡）；token 一樣要自己轉位置 |
| `mdast-util-from-markdown`（micromark）| 自帶原文位置，但要二三十個小套件，Obsidian 語法的擴充要寫 micromark 的狀態機；`marked` 零相依、行為逐一有測試釘著就夠用 |

## 代價

- 多一個依賴。`marked` 的 token 格式改版時轉換要跟著改 —— 每一種語法的 `{text, blocks}` 與位置對照表都有測試釘著
- 第一次打開一個舊專題會多等一下（重抽 Markdown 很快；要是哪天 PDF 的抽取改版，那一次會久）
- 升級後 Markdown 那幾份的語意檢索要回填才回來
- 引文與點註的文字被改寫成拿掉記號之後的樣子（記號本來就不是內容）
- 圖片不顯示 —— 要看圖就開原始快照或原網址；HTML 實體照原文

## 什麼情況要重新考慮

- **要在閱讀器裡顯示 Markdown 的圖片**：先決定「圖片也走擷取管線、存成快照」，不是讓瀏覽器自己去抓（roadmap 記著）
- **網頁也想要排版**：同一套 `blocks` 可以從 Readability 的 DOM 產生 —— 那是另一份 ADR
- **抽取改版要重抽大量 PDF**：升級可能要幾分鐘，那時候要有進度畫面，不能只讓請求等
