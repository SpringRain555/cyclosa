# ADR-0020：固定埠 7433、單一實例、關掉啟動器就結束

**狀態**：已採用（設計決定；實作尚未開始）
**日期**：2026-09-06

> 埠號來自 **2026-09-05 的 UI 設計稿**（頂列顯示 `127.0.0.1:7433`）。
> ADR-0002 定了「單一 Node process ＋ 瀏覽器當外殼」並在代價那一節寫著
> 「**生命週期要自己處理**……否則會累積孤兒 process」——
> 這份 ADR 就是把那條代價變成一個決定。

## 背景

ADR-0002 選了「瀏覽器當外殼」，換來的代價之一是**沒有視窗生命週期可以依附**：

- 使用者關掉瀏覽器分頁，server 還活著
- 使用者再點一次啟動器，會起第二個 server
- 第二個起不來（埠被佔）就報錯，而**使用者要的其實是「開起來」**

第二件事是埠號本身。隨機埠意味著書籤失效、錯誤訊息裡的位址每次不同；
而完全不驗證的固定埠會在被佔用時給出一個看不懂的錯誤。

## 決定

### 1. 固定埠 `7433`，綁 `127.0.0.1`

不是 `0.0.0.0`（ADR-0002 已經否掉），也不是隨機埠。
**固定埠讓書籤、錯誤訊息與文件都能寫死一個位址。**

7433 落在動態／私有埠範圍（49152 以上是慣例保留給臨時埠，
但 1024–49151 的註冊範圍裡未被 IANA 指派的埠是可以用的），
且與常見的開發埠（3000／5173／8000／8080）不衝突。

### 2. 單一實例：埠被佔用時**開既有的那一個**

啟動流程遇到 7433 已被佔用時：

1. 打 `GET http://127.0.0.1:7433/healthz`
2. **回應是 Cyclosa** → 不起新的 server，**直接開瀏覽器指向它**，正常結束
3. **回應不是 Cyclosa 或連不上** → 這是別的程式佔用，**報錯並說明是哪一種情況**

> **這是「使用者再點一次啟動器」的正確行為。** 他要的是「把 Cyclosa 打開」，
> 不是「起一個 server」。報「埠被佔用」對他來說是工具在講自己的實作細節。

`/healthz` 回應要帶一個可辨識的欄位（`{"app":"cyclosa","version":…}`），
**不能只看「有沒有東西回應 200」** —— 那會把別人的服務誤認成自己。

### 3. 關掉啟動器視窗就結束 server

`Launch.ps1` 保持在前景，**直接持有 server 的 process handle**，
視窗關閉時收掉它。

> **2026-09-09：這一條被 ADR-0025 推翻了。** 啟動器現在做完檢查就 `exit 0`，
> server 用 `-WindowStyle Hidden` 起在自己的主控台上，結束改由畫面右上角那顆
> 「結束 Cyclosa」負責（v0.9.0 才有的東西 —— 這份 ADR 寫的時候，那個視窗是
> **唯一**的結束方法）。**這一份不改，它記的是當時的決定。**

**不透過 `npm.cmd` 起 server** —— npm 會再生一層子行程，
拿到的 handle 是 npm 那一層，殺掉它殺不到真正的 server，於是埠還在被佔用。
（`rubricator` 2026-09-04 實測踩過，記在它的 `docs/lessons.md`。）

### 4. 資料庫的鎖與 process 是兩件事

單一實例是**使用者體驗**的決定，不是資料安全的保證 ——
使用者仍然可以手動跑第二個 process 指到同一個資料根。
**SQLite 的 WAL 與交易才是資料完整性的依據**，不是這條規則。

## 考慮過但沒選的

| 方案 | 為什麼不選 |
|---|---|
| **隨機埠** | 書籤失效；錯誤訊息與文件寫不出一個固定位址；使用者沒辦法自己打網址回去 |
| **埠被佔用就報錯結束** | 使用者最常見的操作（再點一次啟動器）會得到一個錯誤，而他想做的事其實完全合理 |
| **埠被佔用就往上找下一個可用的** | 會真的起兩個 server 指到同一個資料根 —— 那是最糟的一種：**兩個都能用，而它們互相不知道** |
| **用 lock 檔做單一實例** | lock 檔在當掉之後會留下來，然後永遠擋著。**埠佔用本身就是一個會自己清乾淨的 lock** |
| **背景常駐 ＋ 系統列圖示** | ADR-0002 已經放棄原生視窗。做系統列就等於走回 Electron 那條路 |
| **只看「埠上有沒有東西回 200」** | 會把別人跑在 7433 的服務誤認成自己，然後把瀏覽器打開到一個不相干的網頁 |

## 代價

- **7433 可能被別的東西佔用**，而使用者沒有辦法改（第一版沒有設定埠的介面）。
  緩解是錯誤訊息要說清楚「7433 被佔用，而佔用它的不是 Cyclosa」。
- **關掉啟動器視窗就結束**意味著使用者必須留著一個 PowerShell 視窗。
  那個視窗看起來像「可以關掉的東西」，而關掉它就會結束程式 ——
  **所以視窗裡必須一直寫著這件事。**
- **`/healthz` 是一個未認證的端點**，任何本機程式都打得到。它只回 app 名稱與版本，
  不回任何資料 —— 但這仍然是一個「本機工具沒有認證」的具體例子（ADR-0002 的既有代價）。
- **單一實例保護不了手動啟動的第二個 process**。它是體驗，不是安全機制。

## 什麼情況要重新考慮

- **7433 在實際使用中被佔用超過一次** —— 那時要加的是「設定埠」而不是換一個埠號
  （換一個只是把同樣的問題延後）。
- **需要在使用者沒開啟動器的情況下跑背景工作**（例如排程重抓）——
  那時「關掉視窗就結束」不再成立，而那是一個新的決定（帶著它自己的
  「怎麼讓使用者知道有東西在背景跑」的問題）。
- 若日後真的做遠端存取，這份 ADR 的每一條都要重新問一次 ——
  而第一個要回答的是認證，不是埠。
