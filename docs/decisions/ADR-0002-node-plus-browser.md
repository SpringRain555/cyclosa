# ADR-0002：單一 Node process ＋ 瀏覽器當外殼，不用 Electron 或 Tauri

**狀態**：已採用（設計決定；實作尚未開始）
**日期**：2026-09-06

## 背景

這個工具要同時滿足四件事：

1. 跑 **WebGL 3D**（力導向圖）；
2. 跑 **LLM 子程序**（`claude -p`、`codex exec`）—— 純前端做不到；
3. 寫檔到 repo 以外的資料根目錄 —— 純前端也做不到；
4. **一鍵啟動**，不要求使用者安裝編譯工具鏈。

Electron 每個 app 各帶一份 Chromium；Tauri 需要 Rust 工具鏈建置，且執行期依賴
Windows 的 WebView2。而使用者的機器上**已經有一個瀏覽器**。

## 決定

**單一 Node process**（Fastify）同時提供 API 與前端靜態檔，**只綁 `127.0.0.1`**，
啟動後開使用者的預設瀏覽器指向它。

`Start Cyclosa.cmd` → `Launch.ps1` → 檢查 Node major → 檢查／建資料根 → 起 server → 開瀏覽器。

## 考慮過但沒選的

| 方案 | 為什麼不選 |
|---|---|
| **Electron** | 打包一份 Chromium（數百 MB）、要自己做更新機制；而且它的原生模組編譯正是「零原生模組」要避開的（見 `environment/versions.md`） |
| **Tauri** | 建置要 Rust 工具鏈；執行期綁 WebView2，而 WebView2 的版本由 Windows 更新決定 —— 3D 與 CSS 行為會隨作業系統飄 |
| **純前端（無 server）** | 跑不了子程序、寫不了 repo 外的檔案、抓網頁會被 CORS 擋死。這三件都是核心功能不是加分項 |
| **綁 `0.0.0.0` 方便手機看** | 把一個沒有認證的本機工具開到區域網路上。要遠端存取應該是另一個決定，帶著它自己的認證設計 |

## 代價

- **沒有原生視窗** → 沒有系統選單、沒有原生檔案對話框（用拖放與 `<input type="file">` 取代）、
  沒有系統列圖示。
- **生命週期要自己處理**：使用者關掉瀏覽器分頁時 server 還活著。要有明確的結束方式，
  否則會累積孤兒 process。
- **同機的其他程式可以存取 `127.0.0.1` 上的 API**。這是本機工具的既有風險，
  但既然這個工具會持有蒐集來的資料，值得寫下來而不是假裝沒有。
- **要先裝 Node。** 對非技術使用者，這是一道真實的門檻。

## 什麼情況要重新考慮

- 需要作業系統整合（全域快捷鍵、系統列、檔案關聯、開機自啟）時。
- 要發佈給非技術使用者，且「先裝 Node 24」實測變成主要放棄點時 ——
  那時的替代方案不一定是 Electron，也可能是打包一份 Node runtime。
