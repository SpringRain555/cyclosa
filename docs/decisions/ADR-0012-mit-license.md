# ADR-0012：採 MIT

**狀態**：已採用
**日期**：2026-09-06

> 這是 14 份裡唯一**已經生效**的決定 —— `LICENSE` 檔在 2026-09-05 建 repo 時就放進去了。

## 背景

`D:\Projects` 底下三個預期會公開的專案（`tagcor-ledger`、`rubricator`、`cyclosa`）
需要一致的授權，理由不只是整齊：

- **`domain/graph` 有已知的跨專案取用點**（ADR-0014），
  兩邊授權不相容的話那件事根本做不了。
- **依賴盤點的紅線要成立**（ADR-0011）—— 而「不能引 AGPL」這條規則的前提，
  就是自己不是 AGPL。

## 決定

**MIT。** `LICENSE` 放在 repo 根目錄，`Test-PublishReadiness.ps1` 會檢查它存在。

## 考慮過但沒選的

| 方案 | 為什麼不選 |
|---|---|
| **AGPL-3.0** | 傳染性讓跨專案取用受限；而且會跟 ADR-0011 的整份依賴盤點反過來 —— 我們自己就會變成別人不能碰的那一類 |
| **Apache-2.0** | 專利授權條款有價值，但這個專案沒有專利、也不預期有。多換來的是長得多的條文 |
| **GPL-3.0** | 同 AGPL 的傳染性問題，只是不涵蓋網路服務 |
| **不放授權** | 法律預設是「保留所有權利」—— 別人不能用。而且那通常不是作者的本意，只是忘了 |

## 代價

- **別人可以拿去閉源商用而不回饋。** 這是 MIT 的定義，不是意外。
- **沒有專利保護條款**（Apache-2.0 有）。
- **已發佈的版本改不回來。** 之後就算改授權，先前那些 commit 仍然是 MIT。

## 什麼情況要重新考慮

若這個工具變成有商業價值的產品，且**需要防止閉源分支**。
那時要先接受上面那條代價：**已經發出去的改不回來**，
新授權只能從某個版本之後開始 —— 而分叉的人可以留在舊版。
