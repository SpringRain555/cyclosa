# ADR-0010：點註採 W3C Web Annotation 選擇器，錨點釘在不可變的快照上

**狀態**：已採用（設計決定；實作尚未開始）
**日期**：2026-09-06

## 背景

**這個問題的標準答案已經存在。** W3C Web Annotation Data Model 定義了一組選擇器，
而 **Zotero 與 Hypothes.is 都同時存兩種**：

| 選擇器 | 性質 |
|---|---|
| `TextPositionSelector` | 字元位移。**快**，但原文一改就全錯 |
| `TextQuoteSelector` | 引文 ＋ 前後文。**抗漂移**，但重複字串會錯位、長文比對慢 |

同時，這個工具的抽取演算法**會改版**（ADR-0003）。如果錨點釘在重構後的排版上，
每次改版所有點註都會漂 —— 而點註漂掉一次，使用者之後就不會再標。

## 決定

1. **直接採 W3C 模型，兩個選擇器都存。**
2. **錨點釘在 `sources/` 的不可變快照上**，不是釘在 `derived/` 的重構排版上。
   重構排版只是**投影** —— 抽取改版重跑時點註不受影響。
3. **筆記同時寫成 `notes/*.md` 純 Markdown**，離開這個工具也讀得到。
4. **點註在圖上是節點**（`note` 表），可以參與關聯 —— 使用者自己的判斷
   跟蒐集來的資料在同一張圖上。
5. **錨點解析失敗時明確標示「找不到原文位置」並保留註記內容**，不靜默丟掉。

## 考慮過但沒選的

| 方案 | 為什麼不選 |
|---|---|
| **自訂錨點格式** | 要自己重新解決漂移問題，而標準答案已經存在，且兩個成熟產品都用它 |
| **只存 position** | 重抽一次就全掉。這正是要避免的那件事 |
| **只存 quote** | 重複字串會錨到錯的地方；長文的字串比對也慢 |
| **錨在 `derived/`（重構後的排版）** | 排版是衍生物，抽取改版就重生成 —— 錨點會跟著全掉 |
| **錨在 DOM 路徑（XPath／CSS selector）** | 對重構後的 DOM 有效，而重構會變。跟上一條同一個問題 |

## 代價

- **兩個選擇器要一起維護**，寫入路徑變複雜，且兩者不一致時要有明確的優先順序
  （先試 position，對不上就用 quote 重找，兩者都失敗才標示失敗）。
- **快照是原始 HTML，字元位置與使用者在閱讀器裡看到的重構排版不同** ——
  UI 必須做一層映射，而那層映射本身可能出錯。
- **PDF 與圖片的錨點模型不一樣。** 第一版的想法是 PDF 用「頁碼 ＋ 頁內字元區間」、
  圖片用矩形區域 —— **那是另一個還沒做的決定**，不在這份 ADR 的範圍。
- 每個點註都存一段引文與前後文 → 資料量比只存位移大。

## 什麼情況要重新考慮

- 出現一種來源型別（影音、互動式頁面）**沒辦法用文字選擇器表達**時 ——
  那時要加的是新的選擇器型別（W3C 模型本身也允許），不是換掉這套。
- 若「錨點解析失敗」在真實資料上超過 1%，先查是不是快照本身被動過
  （那會違反 ADR-0003 的不可變），再考慮改演算法。
