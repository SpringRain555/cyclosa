# Cyclosa

從一個「點」（主題、人物、事件，或一批檔案）出發，用 LLM 主動擴展成一張
**每一條關聯都帶出處**的網。用 3D 力導向圖瀏覽，內建閱讀器與段落點註，
長期累積成可以續接的「**專題**」。

來源語言不限，介面一律**繁體中文**。**純本機、完全離線**（除了它主動去抓的來源）——
單一 Node process 同時提供 API 與前端，只綁 `127.0.0.1`，用瀏覽器當外殼。

> 塵蛛（*Cyclosa*）把吃剩的獵物殘骸與碎屑黏在網上排成一條「隱帶」，那串碎屑組成的
> 形狀看起來像一隻更大的蜘蛛。台灣有特有種蓬萊塵蛛 *Cyclosa formosana*。
> 隱喻就是這個工具在做的事：丟進來一堆資料（含沒用的），工具把它們編進網裡，
> 組成比原本更大的形體。

> 瀏覽器只讓網頁關掉自己開的分頁，所以那裡有一顆按鈕），
> 金鑰的環境變數名稱填了不合格的格式會**當場告訴你**，不再安靜地把它丟掉。

> **v0.21.0：反爬蟲的驗證頁不會再被當成內容存進專題。** 那種頁面多半回 **HTTP 200**，

> 帶那種標頭的 403 也不再被說成「要登入」。理由在 `docs/architecture/fetch-policy.md`。
>
> （v0.20.1 修掉 v0.20.0 來源清單的四個錯，其中一個正是上面那張驗證頁被判成「讀得到」。）

> **匯入的資料不會被抽關聯 —— 擴展也只抽它自己找來的那幾份。** 這一版查清楚了這件事
> （提案 Stage 17，`docs/roadmap.md`）。要把一份人整理的抽取結果寫進專題，
> 開發工具 `tools/dev/apply-extraction.ts` 走的是跟模型一模一樣的路：待查證、引文找不到就沒有那條邊。

**一個網站限流，不會讓整批匯入停下來了**（v0.19.0）。對方說慢一點（HTTP 429／503），
Cyclosa 照它說的等、最多再試兩次；還是不行就那個網站這一輪先不碰，其他網站照跑，
被跳過的那幾項之後可以重跑。線上模型的端點說「排隊」時也一樣會等一下再試。
作業紀錄頁上「對外抓取的規矩」那一列寫的數字，就是程式正在用的數字。

> **雙擊的檔名改了**：`start_cyclosa.cmd`（以前叫 `Start Cyclosa.cmd`）。舊的桌面捷徑要重建。

**擴展用的對話模型可以接任何 OpenAI 相容端點**（v0.18.0）——
線上的服務，或別家本機伺服器。設定頁的「連線方式」選一個，模型從那個端點的清單挑，
金鑰一樣只填環境變數的名字。

> **「回應符合格式」這件事是量出來的，不是假設的。** 各家對 JSON 格式的支援不一樣，
> 而且會變 —— 這個專案自己寫過一句「OpenAI 相容那條只到 `json_object`」，
> 重量一次就不成立了。所以每個端點、每個模型量一次，**設定頁寫著量到什麼、什麼時候量的**。
> 只保證「回一份 JSON」的端點，形狀由 Cyclosa 事後檢查，**不對的一律擋下來** ——
> 那是抽取時防提示詞注入的一層，端點不做就由工具做。

**第一次跑不需要設定任何東西。** 資料放在 `%LOCALAPPDATA%\Cyclosa\data`，
啟動時自己建好；設定頁的「資料位置」看得到它在哪，也換得掉（東西會一起搬過去）。
專題可以**封存**，也可以**刪除**（要逐字打對名稱，而且按之前看得到會失去什麼）。

清單上還會有一份**範例專題**：八條中華民國法律的條文原文、六個實體、
十二條關聯（其中八條待查證，可以直接拿來裁決）。**每一份都指得回它自己那一條的網址。**
語料來自全國法規資料庫的官方開放資料，授權查證在
`docs/research/sample-corpus-licence.md`。刪掉之後不會自己回來 ——
要的話設定頁有一顆重建。

> 範例裡標成「已確認」的關聯是**示範資料**，不是任何人真的裁決過的紀錄。

**跑得起來，而且只跑得動這些**：建立專題 → 貼網址或拖檔案匯入 →
在閱讀器裡讀抽出來的正文 → 在作業紀錄看每一項發生了什麼 →
**在 3D 關聯圖上瀏覽，可旋轉、可點選、可切 2D** →
**手動連線，並且確認／否決／撤回／改判**，每一次都留下稽核紀錄 →
**輸入一個主題 → 工具提幾條切入角度 → 你勾要展開哪幾條 →
新節點帶著出處進來** →
**在閱讀器裡選一段文字（或在圖片上框一塊）做點註，它變成圖上的一個節點** →
**選一塊子圖匯出成證據包**。
**在專題裡搜尋 —— 全文（中文兩個字就查得到）、語意（用字不同也找得到）、
或者兩者一起跑**（完整的 Stage 表在 `docs/roadmap.md`）。

> **搜尋是「索引找候選，正文確認」。** 中文的索引是兩字一組，
> 所以查「台積電」會把「來台積極…累積電力」撈成候選 —— 而**索引裡沒有位置**，
> 分不出來。所以候選拿到之後回去讀正文，驗不過的**留在清單裡標示「可能是誤中」**，
> 不丟掉：丟掉會讓一份只是正文被清掉的資料跟著消失。

> **語意命中不是「誤中」，所以它有自己的標記。** 語意那一路找到的文件
> **本來就不會有那串字** —— 那是它的用途。把它跟跨詞誤中標成同一種，
> 等於對一個正確的結果說「可能是誤中」。它顯示的是**真正命中的那一段**。
>
> **三路的分數不可比**（bigram 次數／`-bm25`／餘弦），所以合併發生在**名次**上，
> 不在分數上 —— 任何一個權重都是在替你決定「這次要偏語意還是偏字面」。

> **匯出的每條引文都能回溯到 `item` 與字元區間，而且是匯出時重新驗過的。**
> 直接把資料庫裡存的位置抄出來，在正文重算過之後會產生一種特別糟的錯：
> **每一條看起來都完整，而區間指到別的地方。**
> 對不上的那幾條**留在檔案裡並標明** —— 省略它們會讓那份檔案看起來比實際上乾淨。

> **來源網站有一份清單，而它的狀態來自你自己抓過的結果。**
> 「這個網域你抓過 12 次，9 次要登入」比任何探測都準，而且不花任何一個請求。
> 探測只補沒抓過的那些，而且**探的是一篇代表性文章不是首頁** ——
> 出版社的首頁一律回 200 而文章回 403。

> **模型設定裡沒有金鑰欄位，只有環境變數的名字。**
> 這個工具不存任何機密：設定檔會被備份、會被同步、
> 會在求助的時候被整份貼出來，而金鑰只在送出請求的那一刻從環境讀一次。

> **點註錨在不可變的快照上，不是錨在重構後的排版上。**
> 抽取換版之後那一段字換了位置，錨點**跟著它走**；真的找不到的時候
> 畫面上寫「找不到原文位置」而且**內容留著** —— 不靜默丟掉，也不錨到錯的地方。
> 點註漂掉一次，之後就不會再有人標。

> **擴展分兩階段，中間有一個人。** 按下去不會直接開始抓 ——
> 它先回幾條子問題（各自帶「這條是從你已有的哪幾份長出來的」），
> **你勾了才開始**。一次跑完的版本少一個畫面而且完全可行，
> 它只是把這個工具變成它想取代的那種東西。

> **匯入本身仍然不產生任何關聯** —— 那是擴展在做的事。
> 圖上的線要嘛是你自己連的，要嘛是某一次擴展抽出來的（進「待查證」）。

> **在 5 萬筆的專題上，這個工具有三項會慢。**
> 2026-09-10 用 5 萬節點／20 萬關聯的合成資料量過六項效能預算，
> **四項沒過**（`docs/environment/performance.md`）：
> 子圖 2 跳約 0.6 秒、工具列的節點數提示約 0.3–0.9 秒、
> 語意檢索約 2.2 秒。全文檢索過了（42 ms，即使那個詞出現在全部 5 萬份文件裡）。
>
> 其中兩項本來是 48 秒與 4.5 秒，v0.12.0 規模驗收時修掉；剩下的差距是實際成本，
> 處置寫在 ADR-0028 與 ADR-0029。**寫在這裡是因為它是你會遇到的事，
> 不是一個內部指標。**

裁決那一段的規矩是這個工具跟「一鍵生成關聯圖」的**全部差別**：

- **每一條關聯都帶出處**，而且「出處 5 筆」與「5 個獨立來源」是兩件事 ——
  互為轉載的來源只算一個
- **可信度不給小數**，給三段等級 ＋ 構成事實 ＋ **你自己過去的裁決比例**
  （樣本不足 30 條就說樣本不足，不給一個看起來精確的百分比）
- **否決是墓碑**：機器不會把你否決過的東西再提一次，
  除非它帶著**先前沒有的出處**回來 —— 那時它會標「曾被否決」
- **機器永遠不得覆寫你的判定**
- **引文在原文裡找不到，那條關聯就不寫進去** —— 模型給的字元位置一律不採信，
  位置由工具自己在正文裡找。**一個指不到原文的出處，比沒有出處更糟**
- **可信度是數出來的，不是模型講的**：三個獨立來源說同一件事才叫「強」

匯入時就會做的事：**同網域之間隔開（預設 3 秒）、遵守 `robots.txt`、對方說慢一點（429／503）
就照它說的等再試、原始位元組存成不可變的快照（SHA-256 命名）、中文與拉丁的索引一起寫**。
其中「間隔」是從伺服器端的時間戳序列驗過的，不是看程式碼推論的。**一個網站限流不會讓整批停下來** ——
那個網站這一輪先不碰，其他照跑（`docs/architecture/fetch-policy.md`）。

## 怎麼跑起來

**雙擊 `start_cyclosa.cmd`。**（2026-09-13 之前叫 `Start Cyclosa.cmd`；舊的桌面捷徑要重建。）它會檢查 Node 版本 → 需要時 `npm ci` 與建置 →
起 server → 開瀏覽器 → **然後自己關掉**。
**第一次啟動不問任何問題** —— 資料根自己建（v0.16.0 起），要換位置在設定頁。

> **那個視窗不是 Cyclosa 的開關**（ADR-0025）：它是一張檢查清單，
> 做完就退場，server 在背景繼續跑。**要結束用畫面右上角的「結束 Cyclosa」。**
> 開不起來的時候，紀錄在 `%LOCALAPPDATA%<<B>>Cyclosa<<B>>logs<<B>>server.log`，
> 或用 `.\tools\Launch.ps1 -Foreground` 看它印了什麼。

> **不要雙擊 `tools\Launch.ps1`。** Windows 對 `.ps1` 的預設動作是「編輯」——
> 雙擊它會打開記事本，而且看起來就像什麼都沒發生。
> `start_cyclosa.cmd` 存在的唯一理由就是這個。

| 指令 | 現況 | 做什麼 |
|---|:--:|---|
| `start_cyclosa.cmd`（雙擊）| ✅ | 一鍵啟動。等同 `.\tools\Launch.ps1` |
| `.\tools\Launch.ps1` | ✅ | 同上，**但要從終端機跑**。`-SkipBuild` 跳過建置檢查、`-Foreground` 讓 server 留在這個視窗裡 |
| `.\tools\Verify.ps1` | ✅ | lint ＋ 型別 ＋ 測試（含 `tests/guards/` 那一區）＋ 兩份 agent 檔比對 ＋ 圖表是否過期 |
| `.\tools\Verify.ps1 -Report` | ✅ | 另外產出**去識別化**的環境快照 |
| `npm run dev` ＋ `npm run dev:server` | ✅ | 開發用，有熱重載 |
| `npm test` | ✅ | 跑全部測試（**數量不寫在這裡** —— 寫死的數字每一版都會漂）|

**已經實際跑過的**（2026-09-07，Node v24.15.0）：`Verify.ps1` 全綠、
build 出來的 server 走完一次真實的匯入 —— 4 個網址（其中一個 404、一個被 robots 擋、
一個內容重複）得到一個 `部分失敗` 的作業，其餘照常寫入；
拖 Markdown／PNG／PDF 進去也走同一條管線，PDF 抽得出文字層與頁數。
`case.sqlite` 現在是 **schema v8**（WAL、trigger、bigram 與 FTS5 索引）。

關聯圖用一份**合成的**圖（四層關聯 ＋ 投影三段各一個實例）**實際截圖看過** ——
四種畫法、選取與一跳提亮、2D／3D 切換、圖例開關逐一確認。
那次看畫面抓到四個測試抓不到的錯（`docs/lessons.md`）。

技術棧：Node 24 ＋ Fastify ＋ Vue 3 ＋ 內建 `node:sqlite`，
抽取用 `@mozilla/readability` ＋ `linkedom` ＋ `pdfjs-dist` ＋ `franc`，
3D 用 `three` ＋ `3d-force-graph`（佈局在 Web Worker 裡跑 `d3-force-3d`）。
**沒有 conda、沒有 Python、沒有原生模組** —— 一鍵啟動只依賴 Node。

擴展與語意檢索用兩個**外部**的東西（都不是 npm 套件）：
`claude` CLI 當 agent、本機 Ollama 當 chat 與 embed —— **chat 也可以換成 OpenAI 相容端點**，
embed 刻意只接本機（線上端點換掉背後的權重不會報錯，只會讓比對安靜地變爛）
（embed 的建議值是 **`qwen3-embedding:4b`** —— 2026-09-09 量過七個候選才定的，
**`bge-m3` 是原本照計畫書帶過來的那個，而它沒有贏**）。
**兩個都可以沒有** —— 沒有的話那些功能會明確報「能力不足」並停手，
其餘照常（全文檢索是純 SQLite，完全不需要模型）。

> **agent 只有搜尋的能力**（`--tools WebSearch`）——
> 它找得到網址，但**抓不了網頁**：抓取一律走同一條擷取管線，
> 因為節流、robots、雜湊、快照只存在於那一層。
> 到設定頁可以看到每個角色現在的狀態與**它的能力宣告**。

## 資料放哪

專題資料庫、原始快照、筆記、日誌都在**專案外**的一個資料根目錄裡，
底下四個頂層資料夾：`cases`（每個專題一個子資料夾）、`backups`、`logs`、`tmp`。
那個資料夾在哪，記在 `%LOCALAPPDATA%\Cyclosa\system_paths.json`（第一次啟動時寫）。

**文件裡一律寫「資料根目錄」而不寫實際路徑**，因為這個 repo 預期會公開。

> 指標檔壞掉或指到不存在的地方時，畫面會說出**「指標檔在哪、它指到哪、那個路徑怎麼了」**
> —— 不是顯示一個空清單。四種失敗四種訊息，各自有測試守著。

## 這個工具刻意不做的事

- **不產生報告。** 只匯出「選取子圖的證據包」（Markdown ＋ 引文 ＋ 來源清單）。
  一個會生成散文的工具，使用者就不會回去看出處了 —— 而出處是這整個東西的重點。
- **不提供回傳整張圖的端點。** 只有子圖 API。**有一條測試守著這件事** ——
  前後端都不得出現指向整圖的路徑。
- **不把分析功能放進 3D。** 3D 只做瀏覽與結構感，精確操作在 2D 面板，而且必須能切 2D。
