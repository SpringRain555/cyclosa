# 儲存版面

**這份是資料根目錄版面、指標檔、snapshot 與衍生物關係的權威。**
資料庫 schema 在 `data-model.md`，不在這裡。

> **現況：設計，尚未實作。** 指標檔還不存在 —— App 沒跑到寫它那一步。
>
> **這一份一律用佔位符 `<資料根目錄>`**，不寫實際路徑。
> 這個 repo 預期會公開，而**私人資料夾的名字本身就是資訊**（ADR-0004）。

## 兩個位置，沒有父子關係

| | 位置 | 進版控？ |
|---|---|:--:|
| 程式 | 這個 repo | ✅ |
| 資料 | `<資料根目錄>` | ❌ **永遠不會** |
| 指標檔 | `%LOCALAPPDATA%\Cyclosa\system_paths.json` | ❌ |

實際路徑的權威來源有兩個，**都不在這個 repo 裡**：
`D:\Projects\_meta\cards\cyclosa.md` 的 `data_root` 欄位，
與本機那份 `.claude\settings.json`（不進版控）。

## 指標檔

```jsonc
// %LOCALAPPDATA%\Cyclosa\system_paths.json
{ "version": 1, "data_root": "…", "updated_at": "2026-09-06T…" }
```

**它只有一個工作：告訴程式資料在哪。** 不放設定、不放狀態、不放快取。

### 四種失敗，四種訊息

REQ-0001 的驗收條件之一是「不要顯示一個空清單」。
**四種情況要分開講，因為使用者要做的事完全不同**：

| 情況 | 碼 | 訊息要說什麼 |
|---|---|---|
| 指標檔不存在 | `IO_POINTER_MISSING` | 第一次啟動。**請選一個資料根目錄** |
| 指標檔壞了 | `IO_POINTER_MALFORMED` | **指標檔的完整路徑** ＋ 「刪掉它重新選，或手動修好」 |
| 指到的路徑不存在 | `IO_DATA_ROOT_MISSING` | **指標檔在哪、它指到哪** ＋ 「那個磁碟接上了嗎」 |
| 路徑存在但寫不進去 | `IO_DATA_ROOT_NOT_WRITABLE` | 那個路徑 ＋ 「檢查權限，或換一個位置」 |

> **「指標檔在哪、它指到哪、那個路徑怎麼了」是同一句話裡的三件事**，
> 缺一件使用者就得自己猜。這是 ADR-0004 那條「多一層間接」的代價，
> 而付這個代價的方式就是把訊息寫清楚。

## 資料根底下

```
<資料根目錄>\
├─ cases\               每個專題一個子資料夾
│  └─ <專題>\
│     ├─ case.sqlite       唯一真實來源
│     ├─ sources\          原始位元組快照。**不可變**
│     ├─ derived\          重構後的排版。**可以整批刪掉重算**
│     ├─ notes\*.md        純 Markdown，離開這個工具也讀得到
│     ├─ agent\runs\<run-id>\   agent 子程序的沙箱工作目錄
│     └─ manifest.jsonl    這個專題抓過什麼、何時、雜湊多少
├─ backups\             migration 前的複本
├─ logs\
└─ tmp\
```

### 一個專題就是一個資料夾

**整個複製走，在另一台機器上打得開**（REQ-0001）。
而市場調查裡 ArchiveBox 的那條標準更強，這個專案照抄：

> **把資料夾整個複製到一台沒有裝 Cyclosa 的機器上，裡面的東西還讀不讀得懂？**

`sources\` 是原始位元組（瀏覽器打得開）、`notes\*.md` 是純 Markdown（任何編輯器）、
`manifest.jsonl` 是每行一個 JSON。**只有 `case.sqlite` 需要工具，而 SQLite 到處都有。**

### `sources\` 與 `derived\`：一個不可變，一個可拋

| | `sources\` | `derived\` |
|---|---|---|
| 內容 | 抓回來的**原始位元組** | 抽取出來的正文與重構排版 |
| 可變？ | **永不** | **可以整批刪掉重算** |
| 命名 | 依 `sha256` | 依 `item id` ＋ 抽取器版本 |
| 點註錨在哪 | **這裡** | 不是這裡 |

**這是 ADR-0003 與 ADR-0010 的實體版面。**
抽取演算法改版時 `derived\` 整批重生成，而點註不受影響 —— 因為它們錨在 `sources\`。

> **`derived\` 與 `case.sqlite` 可能不同步**（重算到一半中斷）。
> 所以要有「整批重算」這個明確動作，不能只靠增量更新。

### `sources\` 只增不減

第一版**沒有清理策略**。這是明知的缺口，不是忘記 ——
清理策略要等到有真實的體積數字再訂（ADR-0003 的代價那一節）。

專題清單頁會顯示「快照佔用」，那個數字就是這個決定的回饋管道。

### `agent\runs\<run-id>\` 是沙箱

`agent` 子程序的工作目錄鎖在這裡（ADR-0006）。

**驗收條件是「這個目錄裡不得出現任何抓取產物」** —— agent 找到的 URL
一律交回主程式走唯一的擷取管線。**在這裡看到 HTML 或 PDF 就是
`PROVIDER_SANDBOX_VIOLATION`。**

> 這是**約定式的邊界，不是作業系統層的隔離** ——
> 子程序仍然是使用者權限下的完整程式。

### `backups\`

migration 前的 `case.sqlite` 複本。**不是版本歷史，也不是回收桶** ——
狀態機裡沒有「已刪除」，刪除就是刪除（REQ-0001）。

## agent 的讀寫規則

| | |
|---|---|
| **可讀** | 本專案全部 ＋ `<資料根目錄>\**` |
| **不可寫** | `<資料根目錄>` 底下的一切。**資料只由 App 自己寫** |
| **不可讀、不可寫** | `<私人資料樹>\` 底下其他任何資料夾 |

**即使在允許範圍內，也不要把實際內容貼進對話**：
摘要式比對（筆數、日期範圍、欄位名）可以直接說；
逐值列出（標題、引文、筆記內容、URL）要先問。

判準是「**離開這段對話之後，這句話還能不能指認出一個人的什麼**」。

> `.claude\settings.json` 的 deny **攔不住 shell，也攔不住 `node -e`** ——
> **成文規則才是界線，不是設定檔。** 完整說明在 `CLAUDE.md`／`AGENTS.md`。
