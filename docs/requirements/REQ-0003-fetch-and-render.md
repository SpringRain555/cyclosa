# REQ-0003：擷取與網頁重構排版

**狀態**：草稿
**日期**：2026-09-06

## 使用者要什麼

貼一個 URL，之後能在閱讀器裡讀到**乾淨的正文**，而不是滿滿的廣告與導覽列。
**而且要知道那份正文可不可信** —— 抽壞了要看得出來，不能靜默交出一段爛正文。

## 驗收條件

- [ ] **同網域請求之間有間隔，而且照設定值走**（可量測：日誌的時間戳序列、`run_item.waited_ms`）。
      數字是設定值，不是這份需求的內容（`architecture/fetch-policy.md`）。
- [ ] **收到 429／503 照 `Retry-After` 退避重試**，還是不行就那個網域這一輪先不碰、**其他網域照跑**；
      run 標 `部分失敗` 或 `失敗`，UI 說明是被對方限流。

> 2026-09-13 改寫（ADR-0031）：這兩條原本寫著秒數下限與「被限流就整批停下、不再試」——
> 那是 agent 做調查時的姿態被抄成了產品的驗收條件。
- [ ] **遵守 `robots.txt`**；不允許的不抓，且**記錄原因**（不是靜默跳過）。
- [ ] snapshot 存**原始位元組 ＋ SHA-256 ＋ 抓取時間**，
      **之後任何重抽都不覆寫它**（ADR-0003）。
- [ ] 每次擷取寫一列進該專題的 `manifest.jsonl`：URL、時間、雜湊、狀態。
- [ ] **抽取信心低的 `item` 在清單與閱讀器裡有可見標記**，不是只寫在日誌。
- [ ] **靜態抓不到內容（JS-only 頁面）時明確標示**，而不是交出一份空正文
      並讓它看起來像「這頁本來就沒東西」。
- [ ] **失敗路徑**：任一階段失敗，`item` 進 `失敗` 狀態並可**重試**；
      重試不產生第二個節點。

## 刻意不做

- **繞過付費牆、登入或存取控制。** 這條在 `AGENTS.md`／`CLAUDE.md`
  是不可違反的規則之一，不是這份文件可以放寬的。
- **第一版不裝 Playwright。** 靜態優先。
  **升級路徑**：先累積「靜態抓不到內容」的實際比例
  （上面那條驗收條件產生的資料），比例高到值得再引，
  而且引進來之後 JS 渲染仍然**只是擷取管線的一個階段**，不是第二條路。
- **整站爬取。** 只抓被指名的頁面。
- **抽取信心值先不做成 0–1 的分數。** 見下面 Q2 —— 一個看起來精確而沒有根據的
  數字，比沒有數字更糟。第一版只做「低信心」這個布林標記。
