# REQ-0006：閱讀器與筆記

**狀態**：**已實作（2026-09-08，Stage 10）** —— 七條驗收條件全部有對應的測試。
**日期**：2026-09-06

## 使用者要什麼

在工具裡**直接讀**（不用跳出去開瀏覽器），選一段文字寫註記，
**那段註記之後找得回來、而且不會因為工具改版而漂掉**。

最後半句是重點。點註漂掉一次，使用者之後就不會再標 ——
跟關聯被機器覆寫一次之後就沒有人再確認，是同一件事。

## 驗收條件

- [x] 第一版支援：**網頁快照／Markdown／純文字、PDF、圖片**。
- [x] 選一段文字建立點註，**同時存 `TextQuoteSelector` 與 `TextPositionSelector`**。
- [x] **重跑抽取（`derived/` 整批重算）之後，所有點註仍指到同一段文字**
      （可驗：重算前後對每個點註的解析結果做比對，差異必須為 0）。
      **這條是 ADR-0010「錨點釘在快照上」的驗收。**
- [x] **點註在圖上是節點**，可以參與關聯 ——
      使用者自己的判斷與蒐集來的資料在同一張圖上。
- [x] **筆記同時寫成 `notes/*.md` 純 Markdown**，
      離開這個工具用任何編輯器都讀得到。
- [x] 閱讀器裡看得到這一份的**抽取信心標記**（REQ-0003）與原始 URL。
- [x] **失敗路徑**：錨點解析失敗時顯示「找不到原文位置」，
      **保留註記內容**，不靜默丟掉，也不錨到錯的地方。

> ### 三條實作時才補上的
>
> **1. 選擇器是伺服器建的，前端只送位置。**
> 前端送引文的話，一個舊分頁或一個改過的 JS 就能存進一則
> 「引文與位置對不上」的點註 —— 而那種點註在畫面上跟正確的一模一樣。
> 同一個判準 Stage 9 已經用過一次（模型給的字元位置一律丟掉，自己找）。
>
> **2. 沒有引文的錨點直接算失敗。**
> 只有位置沒有引文的時候，**沒有任何辦法知道那個位置對不對** ——
> 而一個沒驗過的位置，長相跟驗過的一模一樣。
> 寫入路徑一律兩個都存，所以「只有位置」代表那一列壞了。
>
> **3. 建立點註會同時建一條「註於」的線。**
> 上面第四條寫的是「點註在圖上是節點，可以參與關聯」，
> 而**在焦點加跳數的圖裡，一個零度數的節點等於不存在** ——
> 它只有在你已經知道它的 id 的時候才看得到。
> 那條線是 `origin='human'` ＋ `已確認`（Stage 8 對手動建立的邊定的規矩），
> 所以它不進裁決佇列，也不算進校準比例。

## 刻意不做

- **協作註記／多人。** 這是單機工具。
- **註記的版本歷史。** 第一版沒有；筆記是 Markdown，要版本自己丟進 git。
- **在 `derived/` 上錨定。** 那正是 ADR-0010 排除掉的做法。
- **影音的時間軸註記。** 第一版沒有影音來源。
