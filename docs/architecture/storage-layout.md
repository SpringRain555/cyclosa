# 儲存版面

**這份是資料根目錄版面、指標檔、snapshot 與衍生物關係的權威。**
資料庫 schema 在 `data-model.md`，不在這裡。

> **現況（2026-09-08）：已實作。**
> 指標檔、四個頂層資料夾、`sources/`（**不可變，用 `wx` 寫**）、
> `derived/`（可整批重算）、`manifest.jsonl`（每次擷取一列）、
> `backups/`（migration 前的 `VACUUM INTO` 複本）都在跑了。
> **`notes/` 從 v0.6.0 開始有東西**：一則點註一個 `.md`，見下面。
> **`derived/` 整批重算**那條路也在跑了（`POST …/rebuild`）——
> 「可拋」如果沒有一條真的跑得起來的路，那就只是一句話。
> **`exports\` 從 v0.8.0 開始有東西**（見下面）。
>
> **這一份一律用佔位符 `<資料根目錄>`**，不寫實際路徑。
> 這個 repo 預期會公開，而**私人資料夾的名字本身就是資訊**（ADR-0004）。

## 指標檔

```jsonc
// %LOCALAPPDATA%\Cyclosa\system_paths.json
{ "version": 1, "data_root": "…", "updated_at": "2026-09-06T…" }
```

**它只有一個工作：告訴程式資料在哪。** 不放設定、不放狀態、不放快取。

### 同一個資料夾裡還有一個檔：`providers.json`

```jsonc
// %LOCALAPPDATA%\Cyclosa\providers.json（v2，v0.24.0 起；ADR-0032）
{ "version": 2,
  "connections": {
    "cli":    { "command": "claude", "args": [] },
    "ollama": { "baseUrl": "http://127.0.0.1:11434", "apiKeyEnv": null },
    "openai": null },
  "tasks": {
    "find-sources": { "via": "cli",    "model": "" },
    "angles":       { "via": "ollama", "model": "…" },
    "extract":      { "via": "ollama", "model": "…" },
    "embed":        { "via": "ollama", "model": "…" } },
  "diagnostics": { "logModelCalls": false } }
```

**主鍵是任務**：每個任務各自說走哪一條連線、用哪個模型；連線只定義一次。
**v1 的檔（`chat`／`agent`／`embed` 三個角色）讀到就原地升版**，下一次存檔才寫成 v2 ——
使用者不必做任何事。金鑰欄位存的仍然是環境變數的**名字**，不是金鑰。

**它不塞進指標檔**（上面那條規則），也**不放進資料根**。
理由是資料根的規矩是「整個複製走，在另一台機器上打得開」（REQ-0001），
而這一份裡面裝的是**這台機器**的事實：CLI 在不在路徑上、Ollama 綁在哪個埠、
本機拉了哪個模型。跟著資料搬到另一台機器上，每一條都是錯的。

**檔案不存在是正常狀態** —— 那就是「一個任務都沒設定」，而不是錯誤：
匯入、閱讀器、圖、裁決、全文檢索**完全不需要模型**。

**壞掉的檔案退回預設值，不報錯** —— 這跟指標檔壞掉的處理刻意不同：
指標檔壞掉時使用者的資料在哪沒有別的辦法知道，所以要停下來問；
而 provider 設定壞掉只代表「擴展這一個功能暫時沒設定」。

### 四種失敗，四種訊息

REQ-0001 的驗收條件之一是「不要顯示一個空清單」。
**四種情況要分開講，因為使用者要做的事完全不同**：

| 情況 | 碼 | 訊息要說什麼 |
|---|---|---|
| 指標檔不存在 | `IO_POINTER_MISSING` | 第一次啟動。**請選一個資料根目錄** |
| 指標檔壞了 | `IO_POINTER_MALFORMED` | **指標檔的完整路徑** ＋ 「刪掉它重新選，或手動修好」 |
| 指到的路徑不存在 | `IO_DATA_ROOT_MISSING` | **指標檔在哪、它指到哪** ＋ 「那個磁碟接上了嗎」 |
| 路徑存在但寫不進去 | `IO_DATA_ROOT_NOT_WRITABLE` | 那個路徑 ＋ 「檢查權限，或換一個位置」 |

> **「指標檔在哪、它指到哪、那個路徑怎麼了」是同一句話裡的三件事**，
> 缺一件使用者就得自己猜。這是 ADR-0004 那條「多一層間接」的代價，
> 而付這個代價的方式就是把訊息寫清楚。

### 同一個資料夾裡還有 `logs\`

```
%LOCALAPPDATA%\Cyclosa\logs\
  server.log        ← 這一次啟動
  server.prev.log   ← 上一次
```

**一鍵啟動之後 server 沒有主控台**（ADR-0025：它跑在一個隱藏的主控台上），
所以 stdout 寫到哪裡都沒有人看得到。啟動器用 `CYCLOSA_LOG_FILE`
把日誌指到這裡，每次啟動輪替一份。

**為什麼不放進資料根的 `logs\`**：「資料根讀不到」正是最需要看日誌的
那一種故障，而一個存在資料根裡的日誌在那個情況下寫不出來。
資料根底下那個 `logs\` 是留給**跟資料有關**的紀錄（擷取節流、作業）的。

日誌**不寫來源內容與筆記內容** —— 擋在寫入點，不是匯出時過濾（`shared/log.ts`）。

## 資料根底下

```
<資料根目錄>\
├─ cases\               每個專題一個子資料夾
│  └─ <專題>\
│     ├─ case.sqlite       唯一真實來源
│     ├─ sources\          原始位元組快照。**不可變**
│     ├─ derived\          重構後的排版。**可以整批刪掉重算**
│     ├─ notes\*.md        純 Markdown，離開這個工具也讀得到
│     ├─ agent\runs\<run-id>\<第幾條>\   agent 子程序的沙箱工作目錄（擴展的角度、研究的方向）
│     ├─ agent\research\<研究>\plan\   規劃對話那一支的沙箱
│     ├─ model-calls\<run-id>.jsonl  **預設不存在** —— 診斷開著才有
│     └─ manifest.jsonl    這個專題抓過什麼、何時、雜湊多少
├─ backups\             migration 前的複本
├─ exports\             匯出的證據包。**要拿出去的東西**
│  └─ <專題>\<時間戳>\   evidence-pack.md ／ sources.md ／ evidence.jsonl
├─ logs\
└─ tmp\
```

### 一個專題就是一個資料夾

**整個複製走，在另一台機器上打得開**（REQ-0001）。
而市場調查裡 ArchiveBox 的那條標準更強，這個專案照抄：

> **把資料夾整個複製到一台沒有裝 Cyclosa 的機器上，裡面的東西還讀不讀得懂？**

`sources\` 是原始位元組（瀏覽器打得開）、`notes\*.md` 是純 Markdown（任何編輯器）、
`manifest.jsonl` 是每行一個 JSON。**只有 `case.sqlite` 需要工具，而 SQLite 到處都有。**

### `notes\<點註 id>.md` 的形狀

```markdown
---
id: <點註 id>
item: <它標在哪一份上>
snapshot: <那一份的 SHA-256>
page: 3            ← PDF 才有
created: 2026-09-08T02:33:13.000Z
---

> 引文（原文裡一字不差的那一段）

你寫的註記。
```

前置資料**只放識別碼與座標，引文放進正文的引用區塊**。
那不是排版偏好：這樣就完全不需要處理 YAML 的跳脫，
而**一份不需要跳脫的格式是一份不會因為引文裡有個冒號就壞掉的格式**。

`case.sqlite` 是正本，這一份是複本（ADR-0003）。**寫不出去不算失敗** ——
註記已經進資料庫了，只是純文字那一份沒寫成（`NOTE_MD_WRITE_FAILED`，級別 `partial`）。

### `exports\` 為什麼在專題資料夾**外面**

一個專題資料夾的規矩是「整個複製走，在另一台機器上打得開」（REQ-0001），
而證據包是**要拿出去的東西**。放進專題資料夾只會有兩個後果：
要複製的東西隨著每一次匯出變大，而且**下一次匯出還會把上一次的一起帶走**。

一次匯出一個資料夾，名字是 UTC 時間戳**帶 `Z`**（`20260908-023313Z`）——
一個沒有時區的時間戳在半年後看是一個猜謎，而這個資料夾名很可能是
裡面那份檔案唯一還看得出「什麼時候匯出的」的地方。

**不覆寫上一次。** 證據包是拿去給別人看的東西，
而「我上禮拜寄出去的那一份」必須還在原地 ——
覆寫掉的話，收到那份檔案的人手上拿的東西就再也對不回來了。

三個檔的分工：`evidence-pack.md`（人讀：主張與引文）、
`sources.md`（人讀：那些引文來自哪幾份）、
`evidence.jsonl`（**程式讀：每條引文一列**）。
第三份存在的理由是驗收條件本身 —— 「每條引文都能回溯到 `item` 與字元區間」
是一句程式查得動的話，而只有 Markdown 的話它就只能靠人讀。

### `sources\` 與 `derived\`：一個不可變，一個可拋

| | `sources\` | `derived\` |
|---|---|---|
| 內容 | 抓回來的**原始位元組** | 抽取出來的正文與重構排版 |
| 可變？ | **永不** | **可以整批刪掉重算** |
| 命名 | 依 `sha256` | 依 `item id` ＋ 抽取器版本 |
| 點註錨在哪 | **這裡** | 不是這裡 |

**這是 ADR-0003 與 ADR-0010 的實體版面。**
抽取演算法改版時 `derived\` 整批重生成，而點註不受影響 —— 因為它們錨在 `sources\`。

> **抽取器升版之後、按「重算全部正文」之前**（v0.24.0 第一次發生：v1 → v2，PDF 重排成段落），
> 資料夾裡是 `<id>.v1.json`。讀取找不到現在這一版就**退回讀最近的舊版**，
> 所以升級的下一秒不會每一份都變成「沒有正文」；閱讀器只對「那一版之後這一種資料真的改過」
> 的說一句「這份是舊版抽的」（`EXTRACTOR_CHANGES`：v2 只改 PDF）。
> **刪就每一版都刪**（`removeDerived`）—— 只刪現在這一版的話，舊檔會留下來、而讀取會退回去讀它。
> 重算之後除了點註重解，**關聯引文的字元位置也對回新的正文**（找不到的原樣留著、數出來）。

> **`derived\` 與 `case.sqlite` 可能不同步**（重算到一半中斷）。
> 所以要有「整批重算」這個明確動作，不能只靠增量更新。

### `sources\` 只增不減

第一版**沒有清理策略**。這是明知的缺口，不是忘記 ——
清理策略要等到有真實的體積數字再訂（ADR-0003 的代價那一節）。

專題清單頁會顯示「快照佔用」，那個數字就是這個決定的回饋管道。

### `agent\runs\<run-id>\` 是沙箱

`agent` 子程序的工作目錄鎖在這裡（ADR-0006）。

**驗收條件是「這個目錄裡不得出現任何抓取產物」** —— agent 找到的 URL
一律交回主程式走唯一的擷取管線。**在這裡看到 HTML 或 PDF 就是
`PROVIDER_SANDBOX_VIOLATION`。**

> ### 實際的判準是白名單，而上面那句 HTML 與 PDF 是例子不是清單
>
> 黑名單漏掉的每一種副檔名都是一個安靜通過的違規
> （`.mhtml`、`.warc`、`.webp`、沒有副檔名的一坨位元組…）。
> **這個目錄是我們開的**，所以預設拒絕，只放行
> `.json`／`.jsonl`／`.md`／`.txt`／`.log`（`domain/provider/sandbox.ts`）。
>
> 代價是 agent 想暫存一個 `.csv` 也會被報成違規、整批停下來。
> **那是刻意的**：誤報的處理方式是「來人看一眼再決定要不要放行」，
> 而漏報的處理方式是「沒有人會知道」。
>
> **每條角度／方向一個子目錄**（`…/runs/<run-id>/<第幾條>/` —— 舊的擴展與研究的蒐集同一種形狀），
> 而且**成功失敗都掃** —— 只在成功時掃的話，一個「抓了一堆東西然後才失敗」
> 的子程序就查不到了，而那正是最該被查到的情況。
>
> **規劃對話也有沙箱**（`agent\research\<研究>\plan\`，Stage 19–20）：走 Claude Code 的時候它跟找來源
> 同一套 `--tools` 限制，所以同一條規則、同一支掃描（`application/agent-sandbox.ts`）。
>
> ### 沙箱的路徑要短（2026-09-23 實跑撞到的）
>
> Windows 上**子程序的工作目錄超過 258 字元，`spawn` 就失敗** —— 而且回的是 `ENOENT`
> （看起來像「找不到指令」），同時 stdout／stderr 兩條管線各丟一個沒人接的 `read ENOTCONN`：
> **整個伺服器會停掉**。蒐集的沙箱本來放在 `agent\research\<研究>\collect\<作業>\<第幾條>\`，
> 多兩個 36 字元的 id，資料根夠深就會超過。
>
> 所以：**沙箱一律 `agent\runs\<作業>\<第幾條>\`**（作業的 id 本來就全域唯一，它屬於哪一次研究
> 記在 `run.research_id`）；管線的錯誤一律接住（`infrastructure/providers/spawn-piped.ts`）；
> 真的太長時回 `IO_PATH_TOO_LONG`，叫人把資料根搬到短一點的位置 —— **不是報成「沒設定」**。
>
> 真正在執行這條規則的其實是 `--tools WebSearch`（ADR-0006 的後續）：
> 工具清單裡沒有可以抓、可以寫檔的東西。**這一層是備援。**

> 這是**約定式的邊界，不是作業系統層的隔離** ——
> 子程序仍然是使用者權限下的完整程式。

### `model-calls\<run-id>.jsonl` —— 預設不存在（v0.22.0）

**打開設定頁的「留下每一次模型呼叫的紀錄」才會有。** 一次呼叫一行：
當時送出去的完整提示詞、模型回的東西、**實際跑的那一個模型**、耗時與金額。

| 決定 | 為什麼 |
|---|---|
| 在專題資料夾裡，不在 `logs\` | 裡面有來源正文 —— 它跟專題內容同級，該跟著專題一起備份、一起刪掉。`logs\` 那一份刻意不寫內容（擋在寫入點）|
| 一個作業一個檔 | 查的時候問的永遠是「剛剛那一次跑了什麼」。全專題一個大檔要從頭掃 |
| 記三個任務，**不記 `embed`** | 嵌入的輸出是一串 2560 個浮點數：當文字看不可讀，當素材看離開向量空間沒有意義。它真正該記的（模型、維度、筆數）已經在資料庫裡。判斷寫在 `domain/provider/call-record.ts` |
| 預設關著 | 抽取那一次的提示詞裡是**整份正文**，它長得很快；而多數作業沒有人會回頭看 |
| 只記端點的網域 | **金鑰與環境變數的值永遠不在裡面** —— 跟 `providers.json` 同一條理由：這種檔會被整份貼出來求助 |

> **為什麼需要它**：到 v0.21.0 為止三條路都是解析完就丟，留下來的只有結果。
> 那足以發現「這一次失敗了」，**不足以回答「這條關聯為什麼是錯的」** ——
> 引文找得到不代表關係是對的。使用者遇到的壞例子因此沒辦法重現。

### `backups\`

兩種東西：**migration 前的 `case.sqlite` 複本**，以及**被刪掉的專題資料夾**
（`deleted-<slug>-<時間戳>\`）。

**不是版本歷史，也不是回收桶** —— 而這句話的意思是關於 **app**，不是關於磁碟：

> **app 永遠不讀這個資料夾。** 沒有清單、沒有還原鍵，
> 狀態機裡沒有「已刪除」（REQ-0001）。這裡是留給檔案總管的，不是留給程式的。

> **2026-09-11 更正。** 這一節原本只寫「migration 前的複本」，
> 而 REQ-0001 同時寫著「備份是 `backups\` 的事」——
> **兩句話照字面不能同時成立**，v0.17.0 要加刪除功能時才撞到。
> 挑的是 REQ-0001，理由是「刪除就是刪除」講的一直是狀態機，
> 不是「使用者不准在檔案總管裡把它撿回來」。

刪除是**搬**不是複製（同一個磁碟區的 `rename`，瞬間、不多佔空間），
所以**刪完磁碟空間不會變多** —— 那句話要出現在畫面上，
否則使用者刪了一個 4 GB 的專題卻發現硬碟一點都沒空出來。

> **不要只備份 `case.sqlite`。** 那會得到一份「圖還在、而每一條引文都驗不回去」的東西 ——
> `sources\` 的快照不在資料庫裡（ADR-0003）。
> **一個名字叫備份、而內容缺了證據的檔案，比沒有備份更糟。**

## agent 的讀寫規則

| | |
|---|---|
| **可讀** | 本專案全部 ＋ `<資料根目錄>\**` |
| **不可寫** | `<資料根目錄>` 底下的一切。**資料只由 App 自己寫** |
| **不可讀、不可寫** | `<私人資料樹>\` 底下其他任何資料夾 |

**即使在允許範圍內，也不要把實際內容貼進對話**：
摘要式比對（筆數、日期範圍、欄位名）可以直接說；
逐值列出（標題、引文、筆記內容、URL）要先問。
