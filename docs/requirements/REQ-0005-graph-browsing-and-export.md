# REQ-0005：3D 圖的瀏覽、互動與證據包匯出

**狀態**：草稿
**日期**：2026-09-06

## 使用者要什麼

三件事，順序就是重要性：

1. **看到累積起來的東西長什麼樣**（整體結構感）；
2. **找到某個東西附近有什麼**（焦點＋脈絡）；
3. **把選出來的一塊帶走**，而且帶走的東西裡有出處。

## 驗收條件

- [ ] **預設只渲染子圖**（`focus` ＋ `hops` ＋ `filters`）；
      **沒有任何 UI 路徑會請求整張圖**（可驗：掃前端原始碼，
      不存在對整圖端點的呼叫 —— 因為那個端點不存在，ADR-0008）。
- [ ] **一鍵切換 2D 平面佈局**，切換只改佈局不改資料。
- [ ] 節點與邊**可依型別篩選**（做得到「只顯示人」）。
- [ ] **可以手動建立一條邊**；它一建立就是 `已確認` ＋ `origin='human'`。
- [ ] 可以**確認／否決**機器產生的邊，也可以把否決過的復原。
- [ ] **語意縮放**：近距離顯示標題與縮圖，遠距離只顯示形狀與顏色。
- [ ] 旋轉時有**深度線索**（霧化、近大遠小、選中連線高亮）。
- [ ] **匯出選取子圖的證據包**：Markdown ＋ 引文 ＋ 來源清單，
      **每條引文可以回溯到 `item` 與字元區間**。
- [ ] **效能**：2k 節點時互動 fps ≥ 30。
      **量測條件與機器規格要寫進 `docs/environment/snapshots/`** ——
      一個沒有量測條件的 fps 數字不能拿來做決定。
- [ ] **失敗路徑**：子圖查詢逾時或節點數超過渲染上限時，
      顯示「這個範圍太大，請縮小 hops 或加篩選」，**不是整頁白掉**。

## 刻意不做

- **報告產生。** 只做證據包匯出。**一個會生成散文的工具，使用者就不會回去看出處了** ——
  而出處是這整個東西的重點。
- **把分析功能放進 3D。** 精確操作在側欄的 2D 面板（ADR-0007）。
- **整圖端點**（ADR-0008）。
- **自動佈局的美化參數調到最好看。** 佈局要穩定可預期比好看重要 ——
  同一批資料兩次打開應該長得差不多。
