# Cyclosa

Cyclosa 是在自己電腦上運作的資料整理工具：把網頁與檔案收進「**專題**」，
在閱讀器裡讀原文、選段落存成點註，再用 2D／3D 關聯圖瀏覽資料之間的關係。
搭配模型，可以找候選來源與抽取關聯；關聯的出處能回到原文查核，人工判定不會被模型覆寫。
來源語言不限，介面一律**繁體中文**。

## 快速開始

1. 準備 **Windows 與 Node.js 24.x**（含 npm），確認終端機執行 `node --version` 顯示 `v24.x`。
2. 下載並解壓縮這個 repo，或用 Git 複製到自己的電腦。
3. 雙擊根目錄的 **`start_cyclosa.cmd`**，等待瀏覽器開啟。

不需要先裝模型，也不需要 Python 或額外的原生編譯工具。
啟動器會檢查 Node 版本；尚未安裝相依套件時會執行 `npm ci`，並在需要時執行建置。
**首次安裝相依套件需要網路，也會比後續啟動久。**

第一次啟動會自動建立 repo 以外的資料根目錄，不先詢問設定，並建立一份範例專題。
可以先開範例熟悉閱讀器與關聯圖，再建立自己的專題、貼網址或拖入檔案。
資料位置可在設定頁的「資料位置」分頁查看與搬移；範例若未建立成功，也能在那裡重建。

要停止伺服器，請按畫面右上角的 **「結束 Cyclosa」**；只關閉瀏覽器分頁不會停止它。

## 現況：已出貨（v0.24.3），開發樹已接上研究流程

- **收集資料**：貼網址或匯入檔案，保留原始快照與來源紀錄。
- **閱讀與點註**：閱讀正文；PDF 可切換原始版面與文字檢視，選取段落存成點註。
- **瀏覽與查核關聯**：切換 2D／3D 檢視、手動連線，確認、否決或撤回判定，保留稽核紀錄。
- **搜尋**：全文檢索不需要模型；語意與混合檢索需要本機嵌入模型。
- **研究來源（開發樹，尚未出貨）**：規劃方向、蒐集與初讀、逐筆確認，再建圖抽取關聯；取代舊版擴展。
- **匯出證據**：把選取的子圖匯出為證據包，包含 Markdown、引文與來源清單。

**單純匯入不會自動產生關聯。** 研究建圖抽這次選「進圖」的每份資料，包含對回候選的上傳；獨立匯入不自動抽。
模型提出的關聯不等於事實：沒有可定位的引文與出處，不能標成已確認。

**「研究」（Stage 19–22）已接上，尚未出貨。** 設計已於 2026-09-20 確認。
確認規劃才搜尋、完成蒐集才逐筆確認、開始建圖才抽關聯；逐筆分清預設與人改的。
候選可選進圖、只留書目（已有正文時叫「只留著，不抽」）、丟掉；缺口評估是另外按的模型意見。
書目節點沒有正文，以虛線稜線與淡填表示；人工連線與人指定的書目引用是人的判斷。
取消與中斷保留已寫入結果，繼續建圖只做未完成的候選；刪研究先預覽，不刪圖與資料。
開發工具 `tools/dev/apply-extraction.ts` 共用 `applyExtraction`，記為手動抽取 `extract`；
機器抽取仍進「待查證」，引文位置由程式在正文中找，找不到就沒有那條邊。Stage 24 的全專題整理尚未實作。
實作進度見 `docs/roadmap.md`，已出貨的變更見 `docs/changelog.md`。

## 模型設定

模型服務都是選用的。沒有模型仍可匯入、閱讀、點註、手動整理關聯與全文檢索；
需要模型的任務會說明缺少的能力，不會假裝已完成。

到設定頁的「**模型服務**」設定連線並「儲存並檢查」，再到「**模型分工**」
替各任務選連線與模型，按「儲存並測試」。不同任務可以使用不同服務。
規劃可用 Claude Code、Ollama 或 OpenAI 相容端點；找來源可用 Claude Code 或支援搜尋的相容端點；
初讀與抽取可用 Ollama 或相容端點。設定頁的「來源網站」清單會進研究找來源的提示詞。
未設定模型或能力不足時，研究任務會明確說明並停手；語意檢索則帶提示退回全文。

### 本機 Ollama

先自行安裝並啟動 Ollama，再下載需要的模型。建議值依
`docs/decisions/ADR-0035-non-chinese-models.md` 與
`src/infrastructure/providers/config.ts` 的 `RECOMMENDED_*`：

| 用途 | 建議模型 | 說明 |
| --- | --- | --- |
| 嵌入（語意檢索） | `hf.co/mykor/granite-embedding-311m-multilingual-r2-GGUF:BF16` | IBM 模型，GGUF 由第三方 mykor 轉換 |
| 本機規劃與抽取 | `granite4.2:8b` | IBM 模型；不同任務可共用一個模型 |
| 初讀（尚未出貨） | `granite4.2:8b` | `digest` 的建議值與抽取相同；初讀建議值的實測仍待補 |
| 抽取的較大選項 | `gemma4:12b` | Google 模型，記憶體足夠時可選 |

在終端機下載基本的兩個模型：

```powershell
ollama pull granite4.2:8b
ollama pull hf.co/mykor/granite-embedding-311m-multilingual-r2-GGUF:BF16
```

**建議值只從非中國來源的模型挑選，底座與蒸餾來源也納入判斷；授權限 Apache-2.0 或 MIT。**
這是推薦範圍，不限制你在設定頁選擇自己已安裝的模型。

品質有代價，不能把這份建議當成效能排名第一：

- 在專案的同語料量測裡，繁中查英文原文的跨語言檢索指標 MRR@10，從對照組的 **0.940 降到 0.766**。
- 本機抽取建議值平均每篇抽出的關聯數，從對照組的 **8.2 降到 4.8**；引文命中率為 **93%**，對照組為 **100%**。
- 較大的 `gemma4:12b` 在同輪量測平均抽出 **12.0** 條關聯、引文命中率 **93%**，但需要更多記憶體。

這些是特定語料的結果，不是每份資料都能達到的保證。量測條件與限制見
`docs/research/embedding-choice.md` 與 `docs/research/chat-choice.md`。
嵌入刻意只接本機；換嵌入模型後，請在搜尋面板重新建立語意索引，不要混用不同模型的向量。

### Claude Code 與 OpenAI 相容 API（選用）

- **Claude Code**：需另行安裝並完成登入，在模型服務裡設定 CLI。找候選來源時只開放搜尋能力，
  找到的網址仍由 Cyclosa 的擷取管線處理。
- **OpenAI 相容 API**：在模型服務裡設定端點、金鑰的環境變數名稱與模型。
  對話先走 Responses API，只有 `/responses` 回傳 404 才退回 Chat Completions；
  JSON 格式能力會實際量測，不保證所有標示「相容」的端點都能使用。
  找候選來源另需通過搜尋能力檢查，不是能對話就能找來源。

使用外部模型服務時，相關提示詞與資料內容會送往該服務，也可能產生費用。
請依資料敏感度選擇連線；**在本機運作不代表完全離線**。

## 資料與使用邊界

伺服器只綁定本機迴圈位址，以瀏覽器作為介面。專題資料庫、原始快照、筆記與日誌
存放在 repo 以外的資料根目錄，程式與蒐集的內容分開保存。
讀取已匯入的資料不需抓網頁；下載模型、搜尋來源、擷取網頁與呼叫外部模型則需要相應的網路連線。

- 擷取遵守 `robots.txt`，不繞過付費牆、登入、CAPTCHA 或存取控制。
- 模型只找候選網址，不另開抓取管道；快照、來源紀錄與節流由同一條擷取管線處理。
- 不產生敘事報告，只匯出選取子圖的證據包。
- 不提供整張圖的端點；3D 用於瀏覽，精確操作留在 2D 面板。
