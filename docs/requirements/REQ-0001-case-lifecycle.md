# REQ-0001：專題的生命週期與續接

**狀態**：草稿
**日期**：2026-09-06

## 使用者要什麼

建一個專題，丟東西進去，**離開三個禮拜之後回來還能接著做** ——
不用重新想「我上次做到哪、哪些還沒看、哪些已經確認過了」。

這是這個工具與「一次性的深度研究代理」的分界：那些工具的輸出是一篇報告，
**做完就結束**；這裡的輸出是一個可以再展開的東西。

## 驗收條件

- [ ] 建立專題**三次點擊以內**完成（輸入名稱 → 建立 → 進到專題）。
- [ ] 專題清單每一列顯示：節點數、最後活動時間、**待查證的邊有幾條**。
      最後一項是「回來之後該做什麼」的直接答案。
- [ ] 封存後**重新開啟**，所有狀態與資料不變（可驗：封存前後對 `case.sqlite`
      的內容做比對，除了狀態欄以外必須完全相同）。
- [ ] **再擴展不會改動任何 `origin='human'` 的列**
      （可驗：擴展前後對該子集做 diff，必須為空）。
- [ ] 一個專題就是資料根底下的一個資料夾，**整個複製走之後在另一台機器上打得開**。
- [ ] **失敗路徑**：指標檔不存在、指到的路徑不存在、或資料根不可寫時，
      清單頁顯示**「指標檔在哪、它指到哪、那個路徑怎麼了」**，
      而不是顯示一個空清單。

## 刻意不做

- **專題之間的合併與拆分。** 第一版沒有。
- **跨專題查詢。** 一個專題一個 SQLite（ADR-0003），跨專題要另外設計索引。
- **刪除的復原。** 沒有回收桶 —— 狀態機裡沒有「已刪除」這個狀態，
  刪除就是刪除。備份是 `backups\` 的事，不是狀態機的事。
