# ADR-0025：啟動器做完就退場 —— 推翻 ADR-0020 §3「關掉視窗就結束」

**狀態**：已採用。**2026-09-09（v0.9.1）實作。**
**日期**：2026-09-09

## 背景

ADR-0020 §3 訂的是：`Launch.ps1` 留在前景、直接持有 server 的 handle，
**視窗關掉就把 server 收掉**。那條規則解的是一個真的問題 ——
ADR-0002 選了「瀏覽器當外殼」，於是**沒有視窗生命週期可以依附**，
不處理就會累積孤兒 process。

它也帶著一個當時就寫下來的代價：

> **關掉啟動器視窗就結束**意味著使用者必須留著一個 PowerShell 視窗。
> 那個視窗看起來像「可以關掉的東西」，而關掉它就會結束程式 ——
> 所以視窗裡必須一直寫著這件事。

2026-09-09 使用者的原話是「**我不想讓 cmd 一直在背景**」，
並要求參考 `webscouts` 與 `tagcor-ledger` 的做法。

**而在那之前，前提已經變了**：v0.9.0 在畫面右上角做了一顆「結束 Cyclosa」
（伺服器端的二次確認閘門）。ADR-0020 寫的時候，那個視窗是**唯一**的結束方法；
現在它是第二個，而且是比較差的那一個 —— 它結束程式的方式是「把視窗按叉」。

## 決定

**啟動器是一張檢查清單，不是一個開關。**

檢查完 Node、相依、產物，起 server，**等它真的接受連線**，開瀏覽器，
印三行（網址、怎麼結束、日誌在哪），然後 `exit 0` —— 視窗自己關掉。

**server 用 `-WindowStyle Hidden` 起在自己的（隱藏的）主控台上。**

| 做法 | 有沒有黑框 | 關掉啟動器之後還活著嗎 |
|---|---|---|
| `-NoNewWindow`（v0.8.1–v0.9.0）| 有，而且要一直開著 | 不會 —— 共用主控台，關窗等於送 `CTRL_CLOSE_EVENT` |
| `-WindowStyle Minimized`（v0.8.0）| 有（縮在工作列）| 會 |
| **`-WindowStyle Hidden`** | **沒有** | **會** |

走 ShellExecute 的那兩個**不繼承啟動器的主控台**，所以啟動器可以先走。
（`webscouts` 的 `_scripts\Start-WebScouts.ps1` 是同一個結論，理由也一樣寫在那裡。）

**結束的路只有一條：畫面右上角那顆按鈕。**

### 沒有主控台，所以日誌要有去處

server 的 stdout 現在寫進一個沒有人看得到的隱藏主控台，
所以加了 `CYCLOSA_LOG_FILE`：啟動器把它指到
`%LOCALAPPDATA%\Cyclosa\logs\server.log`，每次啟動輪替一份 `server.prev.log`。

**放在指標檔旁邊，不放在資料根底下** —— 「資料根讀不到」正是最需要看日誌的
那一種故障，而一個存在資料根裡的日誌在那個情況下寫不出來。

`-Foreground` 留給「它為什麼開不起來」：server 跑在這個視窗裡，日誌直接印出來，
不自動開瀏覽器。啟動失敗時的訊息會指向它，也會把日誌的最後 15 行貼出來。

## 考慮過但沒選的

| 方案 | 為什麼不選 |
|---|---|
| **維持 ADR-0020 §3** | 那個視窗唯一的功能是當開關，而 v0.9.0 之後畫面上已經有一顆真正的開關 |
| 視窗留著但最小化 | 還是一個要解釋的東西，而且「最小化的那個是什麼」比「沒有東西」更難懂 |
| 做系統列圖示 | ADR-0020 已經回答過：那等於走回 Electron 那條路 |
| 讓瀏覽器分頁關掉時結束 server（`beforeunload`）| 關掉分頁不該關掉程式 —— 可能開了兩個分頁，也可能是誤關，而那個事件本來就不保證送得出去 |
| server 自己寫日誌到資料根 | 資料根可能還沒設定，而**那正是最需要日誌的時候** |

## 代價

- **關掉分頁而不按結束，就會留下一個看不見的 server。** 它不是孤兒
  （下一次啟動時埠檢查會認出它、直接開瀏覽器），但**畫面上沒有任何地方說它還在**。
  這是拿「不用一直開著一個黑框」換來的。
- **成功啟動之後看不到 server 的即時輸出。** 要看就用 `-Foreground`，
  或去讀 `server.log` —— 而那是一份寫完才看得到的東西，不是一條跟著跑的線。
- **`CTRL_CLOSE_EVENT` 那條保險沒有了。** 以前關掉視窗至少會連帶收掉 server；
  現在如果 server 卡住不理會結束請求，只剩工作管理員。
- 日誌檔會**留在 `%LOCALAPPDATA%`**，而那不是資料根 —— 解除安裝時要記得它。

## 什麼情況要重新考慮

- **出現「使用者以為已經關掉、其實還在跑」的實例** —— 那時要的是一個看得見的
  存在感（系統列、或啟動器每次都報告「它已經在跑了」），而不是回到黑框。
- **需要在使用者沒開瀏覽器的情況下跑背景工作**（排程重抓）——
  ADR-0020 已經預告過這一條，而現在的做法離它更近了一步。
- **server 卡住不理會 `/api/system/shutdown`** —— 那時需要一個外部的結束方法，
  而它應該是啟動器的一個參數（`-Stop`），不是一個要一直開著的視窗。
