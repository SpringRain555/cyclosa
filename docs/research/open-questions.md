## Q1　實體投影的門檻 3 是算出來的，但沒有實測過

**現況**：一個被 *n* 份文件提到的實體，當節點要 *n* 條邊，當邊上標籤要 *n(n−1)/2* 條，
交叉點在 *n*=3。所以預設門檻設 3。

**沒有回答的是**：交叉點是「線比較少」的門檻，不一定是「看起來比較清楚」的門檻。
人在圖上找東西的時候，可能寧可多幾條線也不要多一層節點。

**什麼時候回答**：第一個真實專題累積到 200 個以上節點時，把門檻做成可調，
自己在 2 / 3 / 5 之間切換看看。

## Q2　「抽取信心值」要怎麼算才不是又一個假數字

**現況**：決定要記錄 Readability 的抽取信心值，信心低的標記出來。

**沒有回答的是**：Readability 本身不回傳信心值。要自己算的話，可用的訊號有
正文長度／原始 HTML 長度的比例、有沒有抓到 `<article>`、段落數、連結密度 ——
但把它們湊成一個 0–1 的數字，**很容易做出一個看起來精確而其實沒有根據的東西**。

那正是設計階段對「關聯可信度」的結論：**連續分數只用於排序與粗略的視覺通道，
不顯示成小數給人看。** 抽取信心值大概也該這樣。

**什麼時候回答**：實作 `extract` 那一步之前。屆時先蒐集 30 個真實頁面的那幾個訊號，
看它們跟人工判斷的爛正文對不對得上，再決定要不要有這個值。

## Q3　`agent` 子程序的成本上限要怎麼設才有意義

**現況**：決定每個 run 有逾時、請求數上限、成本上限。

**沒有回答的是**：成本上限要用什麼單位。token 數不等於錢（不同 provider 差很多），
而錢又要靠 provider 回報。**設一個查不到實際值的上限等於沒設。**

**什麼時候回答**：接第一個 `agent` provider（`claude -p` 或 `codex exec`）時，
先看它的 `stream-json` 實際回什麼欄位，再決定上限用什麼單位。

## Q4　繁中介面遇到外語來源時，圖上顯示什麼

**現況**：決定顯示「繁中標題（原文標題）」，原文一鍵可切回。

**沒有回答的是**：3D 圖上的標籤空間很小，兩個標題塞不下。可能的做法有
「近距離才顯示原文」「原文只在側欄」「用語言標記小圖示」——
這是 UI 決定，要看實際的圖才知道。

**什麼時候回答**：3D 圖跑得起來、且有真實的多語來源之後。
