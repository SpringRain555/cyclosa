# REQ-0002：匯入

**狀態**：草稿
**日期**：2026-09-06

## 使用者要什麼

**先丟進來，之後再整理。** 拖一個資料夾、貼一串 URL，東西就進到專題裡 ——
不用先分類、不用先想它屬於哪一個主題。

整理是這個工具要幫忙做的事，不是進門的門檻。

## 驗收條件

- [ ] 拖入一個資料夾**遞迴登記**支援的型別（網頁快照／Markdown／純文字、PDF、圖片）；
      **不支援的型別要列出來**，不是靜默略過。
- [ ] 貼上一批 URL，其中若干抓失敗 → 該 run 進入 **`部分失敗`**，
      **其餘的照常寫入**。（這條就是「部分失敗是一等公民」的驗收：
      一批 40 個 URL 有 3 個 404，其餘 37 個的內容不該跟著消失。）
- [ ] **同一個檔案匯入兩次，靠 SHA-256 認出是同一個 `item`**，不重複建節點；
      UI 要說明它被視為既有項目。
- [ ] 匯入過程中每一項的**目前狀態看得到**（待處理／已擷取／已解析／失敗）。
- [ ] **取消匯入時已寫入的保留**，run 標 `已取消`。
- [ ] **失敗路徑**：單一項目失敗時，UI 要能看到**是哪一項、為什麼**
      （錯誤碼對應的繁中訊息），而不是只有一個「匯入失敗」。

## 刻意不做

- **從其他工具匯入**（Zotero、Obsidian、Pocket）。第一版不做；
  日後要做也**必須走同一條擷取管線**，不另開入口（ADR-0006 第 5 條的同一個理由）。
- **整站爬取。** 只抓被指名的頁面（REQ-0003）。
- **自動分類。** 匯入不做判斷；研究初讀給相關性意見，確認與裁決由人決定。
