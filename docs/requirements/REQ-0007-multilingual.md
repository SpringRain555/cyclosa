# REQ-0007：多語言來源、繁體中文介面

**狀態**：草稿
**日期**：2026-09-06

## 使用者要什麼

**丟進來的東西不限語言，介面一律繁體中文，而且原文永遠找得回來。**

一個把英文資料翻成中文之後就看不到原文的工具，在需要引用的時候等於沒用 ——
而這個工具的全部價值就在引用。

## 驗收條件

- [ ] `item.lang` 由 `franc` 偵測；**偵測不出來記 `und`，不猜**。
- [ ] **中文內容用 bigram 索引，兩個字的查詢查得到。**
      （這條就是那個實測反例的驗收：FTS5 `trigram` 對 2 字查詢命中 0 列。）
- [ ] 拉丁／西里爾等走 FTS5 `unicode61`；`und` 的內容**兩條路都建索引**。
- [ ] 外語節點在圖上顯示「**繁中標題（原文標題）**」，**原文一鍵可切回**。
- [ ] **翻譯標記來源模型與時間**，且**永不覆蓋原文欄位** ——
      翻譯是衍生物（可驗：刪掉所有翻譯欄位後重算，原文完全不變）。
- [ ] 跨語言實體對齊靠 `entity.aliases`（`[{name, lang, script}]`）
      與**選填的 Wikidata QID**；LLM 的判定要帶出處。
- [ ] **UI 字串沒有一個寫死在元件裡**，全部走 `web/src/i18n/zh-TW.ts`
      （可驗：測試掃 `web/src/` 的中文字面值，在 `i18n/` 以外出現就紅）。
- [ ] 中文標題排序用自己維護的 `title_rank`
      （`node:sqlite` 沒有 `createCollation`，見 `architecture/data-model.md`）。
- [ ] **失敗路徑**：翻譯 provider 不可用時，顯示原文並標示「未翻譯」，
      **不是顯示空白，也不是擋住整個畫面**。

## 刻意不做

- **自建跨語言對照表。** 靠 LLM 判定（要出處）與 Wikidata QID 當權威錨點。
- **介面多語。** 只有繁體中文。介面語言與來源語言是兩件事。
- **自動翻譯全文。** 只翻標題與摘要 —— 全文翻譯的成本與錯誤都會累積，
  而使用者真正要讀的時候應該讀原文。
