## 由來

**現在的擴展**（v0.5.0 起）：輸入主題 → 模型從專題裡已有的資料歸納出最多 6 條切入角度
（`MAX_ANGLES`），每條帶一個新聞調查式的立場標籤（時間線、反對意見、資金流向⋯）→ 使用者**至少勾一條、最多五條** →
agent 每條搜一次（每條最多 6 個網址）→ 擷取管線抓 → 抽實體與關聯 → 全部是待查證。

2026-09-18 第一次拿一篇真的論文走完整條路，壞在四個地方：

| 使用者說的 | 查到的原因 |
|---|---|
| 「強迫我選角度，選項不是我要的，也不夠多」| 空選擇直接擋（`EXPORT_EMPTY_SELECTION`）；上限 6；立場標籤是調查報導那一套，不是讀論文那一套 |
| 「擴展到底在做什麼？」| 從按下去到結果之間，使用者看不到模型打算怎麼找、為什麼這樣找 |
| （找到的多半拿不到）| 2026-09-08 第一次真的跑，6 個學術來源 5 個是付費牆 —— 工具照規則不繞過，而畫面上沒有「那你自己去拿」這條路（roadmap Stage 18）|
| （自己匯入的那份從來沒進圖）| 抽關聯只抽擴展自己找來的（`extractInto` 唯一的呼叫點在 `runAngle` 裡，roadmap Stage 17）|

之後的問答裡定下來的（計畫檔 §二，只列跟這一份有關的）：

| 題 | 決定 |
|---|---|
| 流程 | **deep research ＋ plan**：先談出方向（並確認跟專題有關）→ 蒐集 → 候選清單 → 逐筆確認 → 建圖 |
| 角度 | 可以直接用主題開始；要拆方向的話，**切分要明確、有意義、盡量窮舉** |
| 「跟專題有關」| 用已有的資料算（全文檢索），不花錢 |
| 拿不到的 | 選「保留並紀錄」的**進圖**，當只有書目、沒有正文的節點 |
| 整理 | 四項全要：合併重複實體、把沒抽過的抽進圖、找漏掉或標弱的關聯、補繁中名與分類 |
| 翻譯 | 點節點看得到的（標題、摘要）可以切繁中；**全文不翻**；使用者自己的完整譯文當筆記掛上去 |
| 筆記檔 | 使用者準備的筆記檔要能上圖；整理時連筆記一起看 |
| 刪除 | 刪的是**那一次研究的對話紀錄**，不是還原資料庫 |
| 分工 | Claude CLI 當總控制（規劃對話、找來源）；OpenAI 相容端點（使用者的 kano-proxy）負責大量讀取、初步判斷、摘要翻譯、抽取 |
| 「擴展」這個詞 | 改叫「**研究**」|

## 決定

### D1　名稱與範圍

| 中文 | 識別字 | 是什麼 |
|---|---|---|
| **研究** | `research` | 一次「談出方向 → 蒐集 → 確認 → 建圖」的完整過程 |
| **整理** | `consolidate` | 同一個殼，對象是整個專題 |
| **規劃** | `plan` | 談出來的東西：方向清單 ＋ 跟專題的關係 ＋ 刻意不查的範圍 |
| **方向** | `direction` | 規劃裡的一條蒐集方向。取代切入角度，**沒有立場標籤** |
| **候選** | `candidate` | 找到、還沒確認要不要進專題的一個來源 |
| **書目節點** | `item.kind='reference'` | 只有書目、沒有正文的資料節點 |
| **初讀** | `digest` | 模型把一份資料讀一次：有沒有關、繁中標題、繁中摘要（D9）|

新的程式與畫面**不再用「擴展」與 `expand`**；舊的擴展紀錄不改名、不遷移成研究，**升級時清掉**（D17）。

### D2　五步、三道閘門

```
規劃 ──[閘門一：照這份規劃開始]──▶ 蒐集 ──▶ 你這邊 ──[閘門二：完成蒐集]──▶ 確認 ──[閘門三：開始建圖]──▶ 建圖
```

| 閘門 | 按下去之後才會發生 | 會花錢的 |
|---|---|---|
| 一 | 搜尋、擷取、初讀 | 找來源、初讀（各自走「模型分工」表上的那個服務）|
| 二 | 進入確認；**之後不再抓新的** | —— |
| 三 | 抽實體與關聯、建書目節點 | 抽取（「模型分工」表上的那個服務）|

**閘門是工具停下來等人的地方。** 一與三擋在花錢之前；二是「人那一邊做完了」的標記。
每一道按鈕旁邊先說接下來哪幾步會花錢、走哪一個服務（跟設定頁「儲存並測試」同一個做法）。

### D3　研究的狀態（工作流）與作業（執行）分開

`research.status`：

| 從 | 到 | 什麼時候 |
|---|---|---|
| —— | `planning` | 輸入主題 |
| `planning` | `collecting` | 閘門一 |
| `collecting` | `awaiting-user` | 能抓的都抓完了、初讀都讀完了（等你上傳或標原因）|
| `awaiting-user` | `reviewing` | 閘門二 |
| `reviewing` | `building` | 閘門三 |
| `building` | `done` | 建完（一份抽壞不影響其餘 —— 部分完成照 `run` 的規則記）|
| 任何沒結束的 | `abandoned` | 使用者放棄 |

**真正做事的仍然是 `run`**：蒐集是一個 `run`（`kind='research'`，抓與初讀），建圖是另一個。
理由是 `run` 的語意是「一段有開始、有結束的機器工作」—— 「等你上傳」可以等好幾天，
而一個好幾天都是「執行中」的作業，下次打開專題時會被掃成「上次停在半路」（`run-sweep`）。
研究停在 `awaiting-user` 的時候**沒有任何作業在跑**。使用者上傳的檔案走一般的匯入（一筆 `kind='import'` 的作業），
對回候選。

關掉程式再開：`collecting` 的研究照舊停在 `collecting`，它的蒐集作業被掃成「上次停在半路」，
畫面給一顆「繼續蒐集」—— 已抓的不重抓（R13）。

### D4　一個專題同時只有一次研究或整理沒結束

兩次研究同時建圖會同時寫實體對齊與關聯，而「這一次新增了什麼」就數不清了。
**匯入可以並行** —— 它只寫資料節點，不寫關聯。

### D5　規劃對話

- 任務 **`plan`**（新）。**預設走 Claude CLI**：邊查邊談（`WebSearch`，**只看搜尋結果、不抓網頁**，
  跟找來源同一個沙箱與 `--tools` 限制）。**v0.24.2 起 OpenAI 相容 API 也能邊查邊談**（Responses API 的
  `web_search`，ADR-0034），所以第二個選項是它；走本機 Ollama 也可以談，畫面說「這個服務不會上網查」。
  這是 ADR-0032 的例外：`viaOptionsOf` 目前由角色推，`plan` 是第一個「三個服務都可以、能力不同」的任務
- **每一輪都由 Cyclosa 帶完整的訊息串**，不用 CLI 的 `--resume`。現在的呼叫帶 `--no-session-persistence`
  （專題的主題與內容不留在使用者的 Claude 對話歷史裡，`agent-claude.ts`），而 `--resume` 需要把對話存在那邊。
  代價是每一輪重送前面的內容；前綴相同的部分會被 prompt cache 吃掉大半（Q6）
- 模型每一輪交出（照 schema 驗過）：`reply`（給人看的一段話）、`relation`（一句跟專題的關係）、
  `directions[]`（每條：`title`、要找什麼、預期哪一類來源、關鍵詞）、`out_of_scope[]`（刻意不查的）。
  **切分明確、盡量窮舉**寫在提示詞裡，而且 `out_of_scope` 讓邊界看得見 —— 窮舉與否是人看得出來的，不是模型自稱的
- 方向上限草案 **12**（Q11）；超過就說，不靜默截掉
- 閘門一按下去的那一刻，當時的規劃**落成方向表**（一條一列），之後的蒐集、統計、確認都對著那張表。
  使用者手改過的方向標 `origin='human'`；對話裡被模型提過、使用者刪掉的也留著（標「沒採用」）
- 可以**直接用主題開始**：一條方向＝主題本身，零次規劃呼叫（R2，Q1）

### D6　相關性命中：用已有的資料，不花錢

輸入主題的當下跑一次全文檢索（`domain/search` 那一套，bigram ＋ FTS5），
顯示「你已有的 N 份裡 K 份提到它」與那 K 份的標題、命中的一段。**同一份結果放進規劃的提示詞**，
讓模型談方向時知道專題裡已經有什麼。K 是 0 也照說 —— 那本身就是一個資訊（「這是一個新的方向」）。

### D7　候選：能抓的抓、要人拿的人拿、拿不到的說原因

- 每條方向各跑一次找來源（`find-sources`，沿用現在的 agent 與沙箱），候選多一個必填的 `title`
  （書目節點要有名字）與選填的書目欄位（作者、年份、出處 —— 搜尋結果裡有才填，**不叫模型猜**）
- 候選的**取得狀態**：`found` → `fetching` → `fetched`；抓不到 → `needs-user`（帶錯誤碼）；
  使用者上傳 → `uploaded`；使用者標拿不到 → `unavailable`（帶原因）
- **依使用者自己的紀錄多半要登入的網站不去試**（來源網站那一頁的 `preferenceOf`），直接列成「要你拿」——
  試一次付費牆只會多一次被擋，還可能招來驗證頁
- 拿不到的原因四選一：付費牆／沒帳號、找不到這一份（可能是模型編的）、被擋、其他（自由填）
- 上傳的檔案走一般匯入（D3），`candidate.item_id` 指向它；**出處仍然指得回那條候選的原始網址**
  （證據包匯出時寫「使用者上傳，對應 {網址}」）

### D8　抓回來的候選就是資料節點（Q3）

擷取管線照舊建 `item`（快照、雜湊、manifest 都在），閱讀器看得到、可以先讀 —— **但在閘門三之前不抽關聯**。
閱讀器上標「候選 · 研究『{主題}』還沒確認」。確認時選「丟掉」的標**已排除**（ADR-0016 的墓碑：可以復原）。

不另開一個「候選區」（`item.status` 多一個值）：那要改 CHECK（重建資料表）、而且每一個讀 `item` 的查詢都要記得排除它；
而「先讀了再決定」本來就是確認那一步要的。

### D9　初讀：一份讀一次，判斷與繁中一起給（Q2）

任務 **`digest`**（新，`chat`，要 `json_schema`）：抓回來或上傳的每一份，讀一次，回
`relevance`（有／沒有／說不準）＋ 一句理由、`title_zh`、`summary_zh`（兩三句）。

**合成一個任務的理由**：貴的是把正文送出去，不是多回兩個欄位。分成「判斷」與「摘要」兩個任務，同一份正文就送兩次。
走哪一個服務照「模型分工」那張表（ADR-0032）；設成 OpenAI 相容 API 就是 kano-proxy 在讀。

繁中標題與摘要存在 `item` 上（`title_zh`、`summary_zh`、`digested_by`、`digested_at`），**原文欄位永遠不被覆蓋**
（`multilingual.md`）。同一個任務在整理（D13）裡也用來替「沒有繁中的舊資料」補上。

### D10　確認：用數的，不用模型說（Q4）

每一筆候選給最終狀態：**進圖／只留書目／丟掉**。預設值由事實決定：

| 事實 | 預設 |
|---|---|
| 抓到或上傳了，初讀說有關或說不準 | 進圖 |
| 拿不到（任何原因）| 只留書目 |
| 初讀說沒有關 | 丟掉 |

每條方向「找到 N、拿到 K、只留書目 M、丟掉 L」**用數的**。
「請模型評估這次的缺口」是另一顆按鈕，預設不按（它要花錢，而且它說的是意見不是事實）。

### D11　建圖

閘門三之後開一筆建圖作業：

- **進圖**的每一份走 `applyExtraction`（v0.20.0 拆出來的那一半）—— 實體對齊、共同提及、`locateQuote`、
  待查證、墓碑，一條規則都不另寫。**這就是 roadmap Stage 17 的機制，範圍限這一次研究**；
  「專題裡所有沒抽過的」由整理（D13）處理
- `item` 多一欄「抽過了」（`extracted_at`、`extracted_by`）—— 現在分不出「抽過但 0 條」與「沒抽過」
  （`run_item.new_edges=0` 兩者都是 0），而整理要知道哪幾份沒抽過
- **只留書目**的建成書目節點（D12）
- 建完：「在關聯圖上看這一次新增的」（焦點＝這一次新增關聯最多的那一份，v0.23.0 那顆按鈕的做法）

### D12　書目節點

`item.kind='reference'`：`sha256` 是空的（沒有快照）、`status='included'`、標題、網址、為什麼、拿不到的原因、
書目欄位（有才填）。

- **`item.kind` 的 CHECK 要改** —— SQLite 改不了既有的 CHECK，要**重建 `item` 表**（建新表、搬資料、換名、
  重建索引與 trigger）。這會是這個專案第一次重建資料表；migration 之前照舊先 `VACUUM INTO` 一份備份，
  而且要先在真實專題的複本上跑過。同一次把從來沒建過的 `'paper'` 拿掉（程式裡只出現在型別、節點型別篩選的值域與重算時一行 `'paper' → 'pdf'` 的對映）
- 圖上：**跟資料同一個形狀、虛線外框**（「沒有正文」）。不加新顏色（ADR-0018：先問能不能用形狀）；圖例多一列
- 之後補得到正文（使用者上傳）→ **同一個 id 轉成一般的資料節點**，連過的線都還在
- 書目節點跟其他節點怎麼連：Q5

### D13　整理

同一個殼、`kind='consolidate'`。規劃那一步由模型讀專題的摘要（實體表、只有一條出處的關聯、還沒抽過的資料、
筆記的內文），交出**操作清單**（照 schema 驗過）：

| 操作 | 執行走 | 能不能退 |
|---|---|---|
| 合併實體 A ＋ B | 既有的實體合併（`entity_merge`）| 能（取消合併）|
| 抽這幾份 | `applyExtraction` | 能（復原那一筆作業）|
| 加一條關聯 X → Y，附引文 | `applyProposal` ＋ `locateQuote` —— **引文找不到就沒有這一條** | 能 |
| 改實體的型別 | 實體更新 | 能 |
| 補繁中名、補初讀 | `digest`（D9）| 衍生物，刪掉就回原樣 |

每一條**逐條勾**才執行（預設值：Q10）。「只有一條出處的關聯」**不是操作**，是一張給人看的清單 ——
機器不替人把弱的關聯標成強的。

### D14　筆記檔上圖

閱讀器與節點面板上「附上筆記檔」：一份 `.md` 複製進專題的 `notes\`，成為一則**整份的**點註
（`selector_json='[]'`、`note.md_path` 指向它 —— 這一欄 v1 就在了），圖上是一個筆記節點連到那份資料。
內文進索引（搜得到、整理時讀得到）。**匯入頁拖進來的 `.md` 仍然是資料節點**，畫面各自說清楚是哪一種。

### D15　刪除一次研究（Q7）

刪的是：對話、規劃、方向、候選的紀錄，以及那一次的模型呼叫紀錄（診斷開著的話，那裡面有整段對話）。
**不刪的**：寫進圖裡的資料節點、實體、關聯，以及那兩筆作業（它們是「圖上這些東西來自哪裡」的唯一紀錄；
要拿掉寫進去的東西，用既有的「復原這次作業」，ADR-0023）。刪之前畫面說清楚這兩張清單。

**不估算花費**。每一道閘門前說「會不會花錢、走哪一條」；做完之後顯示實際花費（provider 沒回報就寫「不知道」，
不寫 0 —— 跟 `run.cost_usd` 同一條規則）。上限照舊（每次呼叫的請求數上限、CLI 的 `--max-budget-usd`）；
「一次研究的總上限」等量過真實的研究花多少再定（`roadmap.md` 待處理「四」那一列 —— 這裡原本寫 open-questions Q3，
而那一題問的是上限的**單位**，2026-09-06 就搬去 ADR-0006 了）。

### D17　舊的擴展紀錄：升級時清掉（使用者 2026-09-20）

Q9 的兩個選項（留著唯讀／藏起來）使用者都沒選：**「可以直接清除，因為是測試時用的」**。所以：

**升級到「研究取代擴展」的那一版時，每個專題的資料庫第一次打開跑一次一次性的清除**：

| 步驟 | 做什麼 |
|---|---|
| 1 | 照舊先 `VACUUM INTO` 備份整個專題的資料庫（migration 的既有規則）|
| 2 | 只挑真正舊擴展，整批一次套用**復原**規則（ADR-0023 的 `planUndo` ＋ 孤兒實體清除）；手動抽取保留，跨作業參照一起算（Q15）|
| 3 | 刪掉那幾筆作業（`run_item`、`run_angle` 連帶刪），最後 `DROP TABLE run_angle` |
| 4 | 在「匯入與研究」最上面說一次清了什麼：幾筆、拿掉幾份資料與幾條關聯、**為什麼留下那幾份** |

**留下來的照 ADR-0023 那四種**：你建的邊、你裁決過的邊、你讀過或標過點註或排除的資料、還被留下來的邊當出處或端點的那一份（含其他作業）；
`sources\` 的快照一個位元組都不動。

**為什麼不是一顆按鈕**：留著唯讀要為了歷史多維護一套只給舊資料看的畫面（舊的角度表、逐項表）。
**代價**：這一步不可逆，備份是唯一的退路；而且**從現在到那一版之間跑的擴展也會一起被清掉** —— 要留的先說。

| I4 | **閘門一先檢查找來源那一支配不配得上，再落成方向表** | 反過來的話，一次「服務沒設定」會留下一張「已經定案、卻沒有開始」的方向表 |
| I5 | 「你按的取消」→ 等你；**「關掉程式」→ 留在蒐集中** | 差別在於那件事是不是你決定的。取消是一個決定（輪到你了）；關掉程式不是 —— 下次打開該接著做（狀態機那一份有整張表）|
| I6 | 蒐集停在半路時**閘門二也按得下去** | 要你先繞一次「繼續蒐集」才能不要剩下的，是繞一圈 |
| I7 | 一次研究的作業可以有好幾筆（`run.research_id`），花費加總它們 | 「繼續蒐集」開的是新的一筆；只認 `collect_run_id`（最新那一筆）的話，前面那幾筆花的錢就不見了 |
| I8 | `run.unpriced`：這一筆裡**有幾次呼叫沒回報花費** | `cost_usd` 只加總回報過的。一次研究可能同時走 Claude Code（回報）與 OpenAI 相容 API（不回報）—— 只留加總的話，後者那幾次會安靜地變成 0 |
| I9 | 書目節點的**資料面**在 Stage 20（`item.kind` 多 `reference`），**畫法與圖例挪到 Stage 22** | 那時才真的建得出書目節點。重建 `item` 要跟重建 `run` 一起做（同一次備份、同一份 migration）|
| I10 | 候選的**最終狀態與初讀欄位這一版不建** | 一個沒有畫面讀它的欄位只是一個要記得填的欄位。Stage 21／22 用 `ADD COLUMN` 補 |
| I11 | 上傳的那一份把**候選的網址寫進 `item.requested_url`** | D7 說「出處仍然指得回那條候選的原始網址」，而候選那一列會被刪（D15）。寫在資料上才留得住；`source_url` 仍然是檔名 —— 那個網址我們沒有抓過，manifest 也照檔案匯入寫 |
| I12 | 沙箱一律 `agent\runs\<作業>\<第幾條>\` | 第一版放在 `agent\research\<研究>\collect\<作業>\<第幾條>\`，資料根夠深就超過 Windows 的工作目錄上限 —— **伺服器會整個停掉**（`storage-layout.md`）|

## 考慮過但沒選的

| 方案 | 為什麼不選 |
|---|---|
| **擴展留著，在前面加一段對話** | 壞掉的是角度本身（強迫選、立場標籤、從已有資料歸納）；在前面加對話，後面仍然是那個流程 |
| **一鍵到底的 deep research**（交一份報告）| 不做報告；而且一鍵到底就沒有閘門 —— 使用者看不到模型打算怎麼找，也沒有機會在花錢之前改 |
| **候選先放在一個看不見的暫存區** | 要改 `item.status` 的 CHECK、每個查詢都要排除它；而「先讀了再決定」正是確認要的（D8）|
| **CLI 用 `--resume` 接續對話** | 要把對話存在使用者的 Claude 歷史裡，跟 `--no-session-persistence` 的理由衝突（D5）|
| **確認那一步預設叫模型回顧** | 花錢、而且說的是意見；每條方向拿到幾份是查得到的事實（D10）|
| **書目節點用現成的 `kind='paper'`** | 意思不對 —— 書目節點可以是書、報告、要登入的網頁；`'paper'` 是從來沒用過的遺留值 |
| **判斷與摘要分成兩個任務** | 同一份正文送兩次（D9）|
| **候選分成兩列（一條方向一列）** | 同一個網址會被抓兩次、在確認畫面上出現兩次，而「每條方向找到幾份」會數錯（I1）|
| **每一列候選都攤開一個「拿不到的原因」下拉選單** | 實際看過截圖之後改成收在「拿不到…」後面 —— 一次研究幾十列，攤開的話整張表都是選單 |
| **舊的擴展紀錄留著唯讀** | 要為了歷史多維護一套只給舊資料看的畫面；使用者 2026-09-20：「那些是測試時用的」（D17）|
| **全文翻譯** | `multilingual.md`：錯誤與成本都會累積，而真的要讀的時候應該讀原文 |

## 代價

- **這是 v0.5.0 以來最大的一次核心流程改動**，分六個 Stage（roadmap 19–24），每一個照舊收尾（D10 截圖、使用者開起來看）
- **第一次重建資料表**（`item`，D12；`run.kind` 的 CHECK 也要多兩個值 —— 同一種重建）。備份與複本演練是前提，不是選項
- 規劃走 CLI 時每一輪重送整段對話（D5）
- 兩個狀態並存：研究的工作流（`research.status`）與作業的執行（`run.status`）。實作時要寫進 `state-machines.md`，
  而且畫面上要說得出「研究停在等你，沒有作業在跑」
- 設定頁的任務表從四列變五列（`plan`、`digest` 進來，`angles` 退場）
- **舊的擴展紀錄與它寫進圖的東西在升級時被清掉，不可逆**（備份是唯一的退路，D17）
- 書目節點可能是孤立的點（Q5）
- **這是第一次重建資料表**（v10）—— 兩個坑（外鍵開著 `DROP TABLE` 會連帶刪、交易裡關外鍵是 no-op）
  都是實測才看得到的，而它們的症狀都是**安靜的**（`data-model.md` 的「重建資料表」那一節）

## 什麼情況要重新考慮

- **使用者多半直接用主題開始**（R2）—— 那規劃對話就不該是預設路線
- **初讀的「有沒有關」常常錯**（拿論文那個專題的標準答案量）—— 那判斷要退回人手上，初讀只給繁中
- **一次研究的候選常常超過一百筆** —— 確認畫面要有批次操作
- CLI 改了它的對話保存或權限旗標（D5 的前提）
