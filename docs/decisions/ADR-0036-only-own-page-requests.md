# ADR-0036 本機伺服器只收這個工具自己的頁面送來的請求

- 狀態：**已採納**（2026-10-02，v0.25.0）
- 依據：2026-10-02 為模型服務改版做安全檢查時查到的兩條路（下面「背景」）；使用者要求「不要有 LLM 帳號被偷用的可能」
- 補充：ADR-0002（只綁 `127.0.0.1`、不做認證）—— 那一份的取捨不變，這一份補上它沒有擋到的那一半
- 實作：`src/interface/http/request-guard.ts`、`src/server.ts`；測試 `tests/interface/request-guard.test.ts`、`tests/e2e/request-origin.test.ts`

## 背景

ADR-0002 讓 server 只綁 `127.0.0.1`，理由是「不把一個沒有認證的工具開到區域網路上」。
那條擋住了別台機器，**但沒有擋住這台機器上的瀏覽器** —— 使用者開著的任何一個網頁都在本機。
2026-10-02 查到兩條路，都不需要使用者做任何事，只要在 Cyclosa 開著的時候瀏覽到一個惡意網頁：

1. **跨站的「簡單請求」**：`Content-Type: text/plain` 的 POST 不需要預檢，瀏覽器直接送出。
   Fastify 預設的 `text/plain` 解析器把它交給路由；`POST /api/providers` 收到一個字串、解析成預設值，
   **使用者的模型設定整份被蓋掉**。（讀不到回應，但不需要讀。）
2. **DNS rebinding**：攻擊者的網域先解析到自己的伺服器、等頁面載入之後改解析到 `127.0.0.1`。
   對瀏覽器來說那是同一個來源，什麼請求都送得出去、回應也讀得到：
   - 把 `connections.cli.command` 設成任意程式 → 下一次 `GET /api/providers` 的探針（`--version`）就執行它
   - `POST /api/providers/connections/openai/models` 帶自己的 `baseUrl` 與任一個大寫的環境變數名 →
     server 把那個變數的值當成 Bearer 金鑰送到攻擊者的網址
   - 用使用者的 Claude Code 訂閱跑研究（花使用者的額度）

新的瀏覽器有「本機網路存取」的限制，會擋掉其中一部分；**但 server 自己什麼都沒擋**，而那不該靠使用者用哪一個瀏覽器。

## 決定

每一個請求在進路由之前（`onRequest`，body 還沒讀）過三道檢查，再加一條解析器的拿掉：

| 檢查 | 擋什麼 | 為什麼這樣寫 |
|---|---|---|
| `Host` 的主機名只准 `127.0.0.1`／`localhost`／`[::1]`，**埠不限** | DNS rebinding（請求帶的是攻擊者的網域）| 測試聽別的埠；開發時 Vite 代理過來的 Host 是 5173 |
| 會改東西的方法（POST／PUT／PATCH／DELETE）帶了 `Origin`，就必須**完全等於** `http://` ＋ 這個請求自己的 Host | 別的網頁送來的請求 | 只比主機名的話，**同一台機器別的埠**的網頁（另一個開發伺服器、另一個本機工具）也算本機。Vite 代理不改 Host，所以 Origin 與 Host 都是 5173 |
| 會改東西的方法帶了 `Sec-Fetch-Site`，就只准 `same-origin`／`none` | 同上，第二道 | 瀏覽器自己填、網頁改不了的標頭 |
| 拿掉 Fastify 預設的 `text/plain` 解析器 | 跨站的簡單請求 | 前端只送 JSON 與 `application/octet-stream`，兩者跨站送都要預檢，而這個 server 不回 CORS 標頭 |

被擋的回 `IO_REQUEST_FOREIGN`（403；解析器那一種是 415），`correlation_id` 是固定字串
（`foreign-host`／`foreign-origin`／`media-type`）—— 這種請求不值得在日誌裡留一筆「未預期的例外」。

**沒有 `Origin` 的請求不擋**：啟動器的 `/healthz`、`app.inject`、終端機的 `curl` 都不帶它，
而瀏覽器替跨站的 POST 一定會帶（`Origin: null` 也算帶了，照樣擋）。

## 考慮過、沒有選的

| 選項 | 為什麼沒選 |
|---|---|
| **每次啟動產生一個權杖，前端每個請求都帶** | 擋得更徹底，但權杖要從 server 交到頁面上（寫進 `index.html` 或一支端點）—— 而 rebinding 之後那支端點對攻擊者也是同源的。Host 檢查已經把 rebinding 擋在門外；剩下的跨站請求由 Origin 擋。多一個權杖不多擋一種攻擊，卻多一個「頁面拿不到權杖」的故障點 |
| **只比 Origin 的主機名** | 同一台機器別的埠的網頁會被放行 |
| **CORS 白名單** | CORS 管的是「能不能讀回應」，不管「請求有沒有送到」—— 簡單請求照樣送達 |
| **綁 Unix socket／named pipe** | 瀏覽器連不到 |

## 代價

- **用自訂網域開這個工具不再可行**（例如 hosts 檔把 `cyclosa.local` 指到 127.0.0.1）。沒有人這樣用；要支援的話是把那個名字加進白名單，帶著它自己的理由
- **擋不住同一個 Windows 使用者底下的程式**：它本來就讀得到這台電腦上的每一個檔案，包括 CLI 的登入憑證。
  這一份管的是「瀏覽器裡的網頁」，不是本機的惡意程式
- `connections.cli.command` 仍然可以被**這個工具自己的頁面**設成任意程式 —— 那是使用者自己的設定。
  模型服務改版（還沒寫的設計，先給使用者逐條看）打算讓執行檔固定是官方 CLI，到那時這一格就不存在了

## 什麼情況要重新考慮

- 要從另一台裝置（手機、平板）看這個工具 → 那是 ADR-0002 說的「另一個決定」，要有真的認證
- 前端開始送 JSON 與 octet-stream 以外的型別 → 那一種要另外想它跨站送的時候會不會變成簡單請求
