# ADR-0018：每個顏色只有一個意思、每個狀態都有第二重編碼、明暗只表示遠近

**狀態**：已採用。**2026-09-07（Stage 7）實作於 3D 圖**，
規則本身在 `domain/graph/render-rules.ts`（純函式，測得到），
顏色本身在 `web/src/styles/tokens.css`（元件裡不寫色碼）。
**日期**：2026-09-06

> 這份決定**來自 2026-09-05 的 UI 設計稿**，2026-09-06 才回寫進文件。
> 設計稿裡有實際算過的色差數字，**那些數字是這份 ADR 的全部依據** ——
> 沒有它們，下面每一條都只是品味。

## 背景

這個工具要在一張圖上同時表達至少七件事：**這是什麼**（文件／筆記／實體）、
**關聯屬於哪一層**（四層，ADR-0015）、**查證狀態**（待查證／已確認／已否決）、
**可信度**（三段，ADR-0017）、**選取**、**已讀**、**焦點**。

**顏色不夠用。** 這不是「不好看」的問題 —— 顏色用完之後的預設行為是「再挑一個」，
而挑出來的那個會跟既有的某一個在色盲視覺下撞在一起，
**然後沒有人會發現，因為做這個決定的人看得見**。

## 決定

### 三條規則

1. **每個顏色只有一個意思**，跨畫面一致。
2. **每個狀態都有第二重編碼**（形狀、線型、圖示或文字），**永遠不會只靠顏色說話**。
3. **明暗只表示遠近**（3D 的深度），**不表示程度**。

### A 層 · 填色 ＝ 這是什麼（永久不變）

| | 色 | 第二重編碼 |
|---|---|---|
| 資料節點（抓回來的）| `#3987e5` 冷藍 | 方形 ＋ 子型別圖示 |
| 我的筆記（自己寫的）| `#d55181` 暖洋紅 | 方形 |
| 展開的實體 | `#8b93a3` 灰 | **空心** |

**冷／暖是一個有意義的軸**：外面來的 vs 自己寫的。

**節點只有兩個顏色，而第三色不存在 —— 這是算出來的**：

- 深色模式下的合格區間是 **OKLCH L 0.48–0.67 且彩度 ≥ 0.10**
- 掃過整個色相環，區間內有 **149 個候選**
- 能跟藍 `#3987e5` ＋ 洋紅 `#d55181` **全數通過**的第三色，
  **全部落在琥珀／橄欖／綠（色相 60–150）**，而且最好的也只有 **ΔE 12.3**
- **而那一段正好是保留給狀態的兩個顏色**（待查證琥珀、成功綠）

所以**實體改用空心，靠實心／空心分，不靠顏色**。
白色 `#e6e8ee` 整個退出資料層（L 0.931、彩度 0.008，兩項都不合格），
順帶解掉「筆記的白跟線的白撞在一起」。

> 藍 ＋ 洋紅這一對：**色盲 ΔE 15.9 · 正常 26.5**，是所有候選裡最好的。

### B1 層 · 關聯的層 ＝ 用畫法分，不用顏色

四層（ADR-0015）各有畫法：`derived` 摺疊、`named` 漸細、`comention` 線中方塊、
`similarity` 等寬點線。

**漸細 ＝ 有方向、等寬 ＝ 沒有方向。** 粗細是可信度的**排序線索**，讀不出數字。
（漸細取代箭頭：Holten & van Wijk。）

### B2 層 · 查證狀態 ＝ 線上唯一的彩色

| | 色 | 第二重編碼 |
|---|---|---|
| 待查證 | `#d29922` 琥珀 | **虛線** |
| 已確認 | `#8b93a3` 灰 | 實線 |
| 已否決 | `#6b7280` 灰 | **中間打叉**，預設隱藏 |

**已否決沒有自己的顏色，因為色相真的用完了。** 四個候選家族全部實測失敗：

| 候選 | 結果 |
|---|---|
| 洋紅 `#d55181` 給已否決 | **FAIL** 對已確認灰 CVD ΔE **5.2** ← 洋紅與中性灰在綠紅色盲下幾乎同色，正好敗在想分開的那一對 |
| 我的筆記改暖色 `#c96a3c` | **FAIL** 對待查證琥珀 正常視覺 ΔE **12.5**（低於 15 硬底線）|
| 已否決改紫 `#8156c0` | **FAIL** 對資料藍 正常視覺 ΔE **14.3** |
| 選取改青綠（低亮度）| **FAIL** 對洋紅 CVD ΔE **7.6** |

**所以改用「打叉」—— 形狀，不是顏色。** 而「劃掉」本來就是它的意思，
**色盲、灰階列印、強制對比模式下都讀得出來**。
節點的「已排除」共用同一套畫法（ADR-0016：兩者都是墓碑）。

### C 層 · 環 ＝ 現在的狀態（暫時、可疊加）

| | 畫法 |
|---|---|
| 選取 | **青色外環** `#35d6c4` |
| 已讀 | **灰色內環** `#8b93a3`（長期狀態，隨時看得見）|
| 焦點 | ＝轉動中心。白色準星 ＋ 傾斜環**疊在節點上**，不取代節點自己的畫法 |

**外環＝你在哪，內環＝讀過了**，兩個一起出現就是「選取＋已讀」。

> **2026-09-09：已讀的那個內環被 ADR-0024 拿掉了**（改標在標籤的字重上）。
> 它畫得比方塊的側影小，所以方塊永遠吃掉它一部分 —— 而吃掉多少隨著轉動在變。
> 焦點的白色準星則早在 ADR-0022 就換成紫色的環。**這一份不改，它記的是當時的決定。**

青 `#35d6c4` 是唯一過關的選取色：它不會變成最差的那一對
（最差仍是既有的洋紅↔藍 15.9），對琥珀 **17.2／22.6**，對背景對比也過。

**「剛讀過」不是獨立狀態 —— 它就是選取。** 從閱讀器回來那一份就是選取，
點下一個節點時選取自然轉移，舊的只留下已讀內環。

**一跳鄰域只提亮、不加框；其餘維持原亮度不改暗。**
為了讓提亮有空間，休息狀態本來就固定帶一點霧化底 —— **選不選都一樣，不會忽明忽暗**。

### D 層 · 只在面板與文字，不上關聯圖

`#3fb950` 確認 · `#f85149` 失敗 · `#58a6ff` 主要動作 · `#35d6c4` 選取。

**綠對紅在綠紅色盲下只差 ΔE 2.2** —— 所以這四個**一律配圖示或文字**，
永遠不會只靠顏色說話。**`#f85149` 在關聯圖上永不出現**：紅色留給真的壞掉的東西，
而「已否決」不是壞掉。

背景 `#0f1115` `#171a21` `#1e222b` `#252a35` ·
框線 `#242832` `#313745` `#3a4150` `#4a5160` ·
文字 `#e6e8ee` `#c9ccd6` `#9aa0ae` `#6b7280`

## 考慮過但沒選的

| 方案 | 為什麼不選 |
|---|---|
| **每個狀態各給一個顏色** | 實測不可行。上面那張表就是四次嘗試的結果 —— **色相真的用完了** |
| **用明暗表示可信度** | 明暗已經被 3D 的遠近佔用。同一個視覺通道表示兩件事，在旋轉時會互相汙染 |
| **只做淺色主題** | 那要重算整組色差（合格區間不同）。而 3D 圖在深色底上的深度線索明顯得多 |
| **顏色不做無障礙檢查，之後再說** | 顏色一旦鋪進整個 UI 就改不動了 —— 改一個顏色要動每一個用到它的地方，而那時已經有幾十處 |
| **用第三方配色工具挑一組就好** | 那些工具不知道「琥珀與綠要保留給狀態」這個限制。**限制是這個專案自己的，所以候選集也是** |

## 代價

- **只有兩個節點顏色**，所以型別的區分很大一部分要靠圖示與形狀 ——
  而圖示在遠距離的語意縮放下會消失。遠看時只分得出「冷／暖／空心」三類。
- **實體用空心**，在密集區域比實心難看見。
- **深色主題是唯一選項**，第一版沒有淺色。在明亮環境或列印時體驗較差。
- **每個狀態都要第二重編碼**意味著每加一個狀態，就要想一個新的形狀或線型 ——
  而形狀的空間也是有限的，只是比顏色大。
- 這組數字**綁在深色骨架上**。骨架的背景色一改，合格區間就變了，全部要重算。

## 什麼情況要重新考慮

- **要加淺色主題** —— 那時整組色差要重算，因為合格區間依賴背景亮度。
  **不是把顏色調亮一點就好。**
- **出現第八件要在圖上表達的事** —— 那時先問「它能不能不上圖」（放側欄），
  再問「能不能用形狀」，**最後才問顏色**。這個順序不能反過來。
- 若實測發現使用者分不出「漸細」與「等寬」（那是關聯有無方向的唯一線索），
  要加的是第二重編碼，不是換顏色。
