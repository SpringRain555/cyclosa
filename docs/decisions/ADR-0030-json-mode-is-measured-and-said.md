# ADR-0030 線上端點的 JSON 格式：量的，不是宣告的；降級要說出來

- 狀態：**已採納**（2026-09-11，Stage 16）
- 修正：ADR-0006 第 3 條的適用方式（不是推翻它）

## 背景

這個工具對 `chat` 的每一種用法都要一份符合 schema 的 JSON（`TASK_ANGLES`、`TASK_EXTRACT`
都要求 `json_schema`）。Stage 16 之前只有本機 Ollama 一種端點，而它的原生 `format`
用受限解碼**保證**形狀，所以這件事從來不需要被問。

線上的 OpenAI 相容端點不一定有那個保證。實際上有三種行為：

1. 收 `response_format: json_schema` 並真的套用
2. 只到 `json_object` —— 保證「是一份 JSON」，形狀不管
3. **收了 `json_schema` 卻安靜地忽略** —— 形狀上看不出來

而這個專案自己寫過一句「OpenAI 相容那條路只到 `json_object`」，
2026-09-11 重量一次就不成立了（`research/openai-compat-json-schema.md`）。

## 決定

### 一、支援度是量的，每個「端點＋模型」各量一次，帶著時間

用一份模型不可能自己猜到的 schema、一句往反方向拉的提示詞量
（第三種行為在這一題會回一句自我介紹，而不是被當成支援）。
結果存在 `%LOCALAPPDATA%\Cyclosa\provider-checks.json`，**不過期，但畫面上照實顯示量的時間**，
「實際打一次」那顆按鈕會重量。沒量過就在**第一次真的跑任務之前**量。

### 二、`object` 模式由這一側事後驗證，而且那是被允許的降級

端點只到 `json_object` 的時候，schema 寫進系統提示，回應由 `conformsTo` 驗 ——
**形狀不對的一律擋下來**（`PROVIDER_OUTPUT_SCHEMA_MISMATCH`），不交出一份沒被限制過的輸出。

**兩種模式都驗。** `schema` 模式下驗不過，代表端點說它支援卻沒有做到。

### 三、`none` 是停手，不是降級

兩種都不成立的端點，需要結構化輸出的任務一律停（`PROVIDER_JSON_UNSUPPORTED`）。
**不從散文裡撈 JSON** —— 那會在模型換一種寫法時安靜地少撈幾條。

### 四、本機 Ollama 不改走 `/v1`

它現在也支援 `json_schema`，但 `/v1` 送不了 `think: false` 與 `num_ctx`。
同一題慢 9 倍（0.45 秒 → 4.1 秒），而那兩個欄位 2026-09-09 量過是決定性的。

## 為什麼第二條不違反 ADR-0006

ADR-0006 第 3 條：「配不上就停手，**不靜默降級**。」它擋的是兩件事：
能力不夠的時候自動換一個比較弱的來跑，以及**使用者看不到結果來自什麼條件**。

`object` 模式兩件都沒有：

| ADR-0006 擋的 | `object` 模式 |
|---|---|
| 換一個比較弱的 provider | 同一個端點、同一個模型 |
| 能力打折 | **守住的性質沒有變**：能通過的只有 schema 描述的形狀。機制從「生不出來」變成「生出來會被擋」|
| 靜默 | 設定頁顯示是哪一種、什麼時候量的；各任務那張表標出「事後檢查格式」；作業紀錄寫下這一次兩個任務各用了哪一種 |

那個性質是 `expansion-prompts.ts` 檔頭寫的三層防護的**第二層**
（「能吐的只有實體與關係」）。第三層（引文要在原文裡找得到、一律進待查證）不受影響。

## 代價

- **量測要花錢。** 線上端點每個模型一到兩次很小的請求。第一次跑任務時自動量，
  那一筆不在使用者按下去之前說明 —— 只在設定頁的「還沒量過」那一句裡提過。
- **`object` 模式會多失敗幾次。** 模型不受限的時候，形狀不對的比例比受限解碼高，
  每一次都是一筆付了錢卻被擋下來的呼叫。沒有量過比例是多少。
- **schema 寫進提示詞會多花 token**，而且提示詞裡的 schema 也可能被夾帶的網頁內容「反駁」——
  那正是為什麼形狀由驗證器把關，不是靠模型聽話。
- **驗證器只支援十二個關鍵字**（`conformsTo`）。遇到不認得的一律判不通過（fail closed），
  所以哪天 schema 用了 `pattern`，`object` 模式下那個任務會一直失敗，而不是安靜放行。
  `tests/domain/schema-check.test.ts` 會先紅。
- **`/models` 會列出不能對話的模型**（嵌入、語音）。這裡沒有辦法在列清單時濾掉 ——
  協定裡沒有那個欄位。選到的話量測會回 `none`，並帶出對方自己說的原因。

## 什麼情況要重新考慮

- `object` 模式的失敗率量出來很高（例如超過三成）→ 那個端點其實不適合，
  應該改成停手而不是降級
- OpenAI 協定加入「關掉思考」與「context 大小」的標準欄位 → 本機 Ollama 可以改走 `/v1`，
  少維護一條傳輸
- 出現一個端點在 `schema` 模式下常常驗不過 → 第一條的量測設計抓不到它，要加一題
